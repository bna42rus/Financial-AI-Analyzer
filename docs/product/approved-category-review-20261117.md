# Согласованные категории, правила и проверка — 17.11.2026

Источник: прямое согласование владельцем в чате и макет всех причин проверки от 17.11.2026. Дополняет PDF v1.3 и amendment от 16.11.2026 в указанной области. Новых разделов настроек и обязательных переходов в карточку нет.

## Распределение категорий

Магазин, тип, финансовый смысл, распознанное назначение и пользовательская категория определяются раздельно. Имена общих профилей едины при всех согласованных написаниях. Суммы, банковские факты, связи и части не изменяются классификатором категорий.

Создание/переименование/перемещение категории не запускает ИИ и не распределяет историю. Существующая кнопка доступна только при полезной допустимой работе, доступном сервисе и отсутствии параллельного импорта/неопределённого результата прежнего запроса. Повтор одинакового завершённого прохода не оплачивается заново.

Ручное значение конкретного поля, включая явное «Без категории», имеет приоритет. Затем действуют личные правила, явные смысловые привязки пользователя и автоматическое распознавание. Неизвестный финансовый смысл, части, противоречивые источники и личные назначения не обходятся моделью.

Новые пользовательские категории, в том числе после полного удаления прежних, могут быть сопоставлены с распознанным назначением после нажатия кнопки. Используются только актуальные ID, роли и пары родитель/подкатегория. Произвольные «Работа/Семья/Личное» сами не доказывают цель платежа. Нет подходящей категории — остаётся без категории. Равнозначные подкатегории — подходящий родитель без произвольного выбора ребёнка. Категории не создаются и не восстанавливаются молча.

Уверенные непротиворечивые сопоставления явного прохода могут сохраняться по ID для будущих загрузок. Явные пользовательские привязки остаются закреплёнными; автоматические допускают уточнение только в новом запрошенном проходе после изменения структуры. Переименование сохраняет прежнее назначение. Ручные решения одной операции сами по себе не становятся общими привязками.

Существующие Preview/Merge/Delete/Hide/Move категорий сохраняют dependency checks, переносы и историю. Перенос подкатегории сохраняет её ID и согласованно обновляет родителя у зависимостей. Удалённые личные зависимости требуют настройки; не заменяются догадкой. При отсутствии подходящей подкатегории допустим родитель без неё.

Отсутствие признаков доставки у известного продуктового магазина означает базовую покупку продуктов по справочнику. Доставка назначается по явным согласованным признакам, включая латиницу и специальные профили, без ложной неопределённости «магазин или доставка».

## Проверка операций

Все обычные поля доступны в текущей проверке: магазин, тип, финансовый смысл, категория, подкатегория, контрагент и комментарий. Участие в аналитике сюда не добавляется. Неопределённые/сомнительные поля сверху, определённые в «Других полях». Во время редактирования расположение не прыгает. Зависимые поля видны даже до выбора смысла/родителя; недоступность объясняется рядом. Пустые необязательные поля не заставляют выдумывать сведения.

Название операции открывает карточку добровольно. Отдельной кнопки «Открыть карточку для проверки» нет. Структурные причины разбираются непосредственно здесь через существующие редакторы:

| Причина | Данные и действие |
|---|---|
| possible_duplicate | Две записи, суммы/даты/счета; одна операция с просмотром последствий либо разные записи; банковские источники сохраняются |
| unlinked_refund / link_uncertainty | Другая сторона, вид, сумма и состояние связи; выбрать, изменить, подтвердить или отклонить |
| dependency_conflict / capacity_conflict | Конкретная связь/часть и несоответствие; исправить сумму/сторону/часть либо убрать ошибочную связь |
| component_conflict | Общая сумма, сумма частей и остаток; существующий редактор распределения |
| category_not_defined у части | Редактируется категория этой части, не только родителя |
| incomplete_credit_data | Известная сумма и недостающий состав; основной долг, проценты, комиссии, страховка не выдумываются |
| unsupported_installment_contract | Достоверные тип/смысл/счёт и состав по поддерживаемой модели; сервис не создаёт договор или долг |
| parser_uncertainty / import_issue / zero_amount | Сомнительное банковское значение и доступное описание; отдельная коррекция, сохранение происхождения |
| source/posted_timezone_conflict | Даты из источников, отдельная коррекция операции или проводки |
| source/posted_timezone_unknown | Требуется уточнить именно банковскую дату, если она не определена; известная локальная дата не становится ошибкой из-за отсутствия пояса |
| conflicting_rules | Применимые личные правила и их назначения; исправить текущую операцию либо существующие правила |
| user_requested_review | Существующее снятие своей отметки |
| low_kind/role/category_confidence, unresolved_role/transfer, category_conflict | Соответствующие основные поля и конкретная причина |

Редакторы работают с общим черновиком. Поля не теряются при открытии частей/связей и при ошибке. Изменения полей, частей и связей применяются одним согласованным действием через существующие preview/commit и проверки владения. Объединение дублей сохраняет отдельный просмотр последствий; несохранённые правки сначала применяются.

Снимается только реально исправленная причина. Одна операция может иметь несколько причин. «Пропустить» ничего не подтверждает. Проверка банковских полей не подтверждает категорию, дубли или связи. Коррекция даты проводки не переписывает дату операции. Напечатанное местное время не теряется и неизвестное время не выдумывается.

## Две галочки и личные правила

Без галочек изменяется текущая операция. «Применить к похожим» затрагивает только выбранные существующие операции. «Запомнить» создаёт личное правило для будущих. Обе галочки совмещаются. Комментарий остаётся локальной правкой и не мешает сохранению поддерживаемых назначений правила.

Массовое применение не стирает защищённые поля соседних операций. Связи с конкретными операциями, решения о дублях и суммы частей не копируются на похожие записи. Переводы группируются только по устойчивому банковскому совпадению, не по имени/сумме/последним цифрам. Правило своего перевода допускает оба направления; обычное направленное правило не меняет встречное направление.

Контрагент обозначает сторону, а не автоматически цель всех её платежей. Подтверждённые алиасы и личные правила принадлежат владельцу. Переименование сохраняет ID, одинаковые имена не объединяются. Создание контрагента без запоминания не создаёт правило. Существующие история, preview применения правил и редактирование зависимостей сохраняются.

## Ошибки

Валидация красным у конкретного поля/редактора; повторяющей общей плашки для тех же ошибок нет. Предупреждения жёлтые. Неверные суммы/даты, несовместимые роли, чужой родитель, удалённые категории/контрагенты, конфликт правил и превышение доступной связи не сохраняются молча. При сетевой неопределённости повторяется тот же action ID. При смене revision/generation данные не перетираются; черновик сохраняется до явного решения. Истечение доступа и технические работы не обходят серверную авторизацию. Ошибка составного действия откатывает все его изменения.
