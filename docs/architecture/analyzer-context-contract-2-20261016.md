# Контракт №2: контекст диалога — согласован 16.10.2026

Основание: задание владельца 16.10, раздел 5; Master PDF 4.5, 26.2, 26.5–26.8.
Статус: владелец согласовал правила 16.10.2026. Это утверждённые продуктовые
требования. Они ещё не полностью реализованы; исторические goldens и новый
JSON-контракт этим решением не изменяются.

1. **Два вида памяти.** В пределах одного чата сохраняются очищенная история
   общения и отдельно точные условия подтверждённых финансовых задач.
   Модель понимает смысл по минимально нужной истории; программа хранит
   фильтры/связи и считает. Память не даёт прав на финансовые инструменты.
2. **Продолжение меняет только названное.** Период, категория, сумма, счета,
   сравнение и формат сохраняются независимо. «А по категориям?» меняет
   формат, сохраняя порог суммы, даты и остальные ограничения. Явные слова
   пользователя имеют приоритет перед глобальными фильтрами.
3. **Смена метрики.** Короткое явное продолжение «А доходы?» меняет метрику
   в той же задаче и сохраняет остальные условия. Если сочетание условий
   нельзя выполнить, нужен понятный вопрос/отказ функции; скрыто сбрасывать
   ограничения нельзя. Самостоятельный вопрос начинает задачу на текущих
   глобальных фильтрах. Определение самостоятельности по смыслу, не одному
   начальному слову «А». Явное «новый расчёт с нуля» однозначно начинает новую
   задачу, сохраняя обязательные ограничения доступа/фиксированного набора.
4. **Возврат к прошлой задаче.** «Вернись к первому сравнению расходов»
   выбирает указанную задачу, а не последний ответ вообще. Служебные UUID
   пользователю не нужны. При нескольких подходящих вариантах — короткое
   уточнение, если ссылка не позволяет выбрать однозначно.
5. **Ошибки.** Ошибочный/неподдержанный запрос не перезаписывает последнюю
   подтверждённую задачу. Неуспешная просьба остаётся в истории как
   неподтверждённая. Если пользователь продолжает именно её, её смысл можно
   заново разобрать вместе с уточнением и полностью проверить; невалидный
   JSON не становится проверенным родителем. Если связь неясна, уточнить,
   а не незаметно применить короткую фразу к более старому расчёту.
6. **Общие и посторонние темы.** Финансовый совет, общая информация или
   короткое перенаправление не стирают активную задачу расчёта. «Вернёмся к
   расходам» после такого ответа продолжает подходящую финансовую задачу.
   Полностью посторонняя тема не даёт доступа к базе или web search.
7. **Интерфейс.** Ручное изменение фильтра применяется к соответствующей
   группе следующего расчёта; остальные условия сохраняются. В том же ходе
   явное текстовое условие важнее UI. «За период, выбранный сверху» явно
   берёт текущий UI-период, в том числе если предыдущая задача имела другой.
8. **Актуальность и границы.** Продолжение заново считается по текущей БД;
   старые суммы не источник расчёта. Разные чаты не смешивают контекст.
   Фиксированный набор операций нельзя расширить сменой даты/категории.
   Личные постоянные предпочтения и правила — отдельный будущий контракт.

| Последовательность | Согласованное поведение |
|---|---|
| Расходы на продукты за сентябрь → «А в августе?» | Август, продукты и прочие ограничения сохранены |
| Доходы по операциям от 1000 до 2500 → «А по категориям?» | Меняется формат; порог 1000–2500 сохраняется |
| То же → «А без ограничения по сумме?» | Снимается только порог, формат/период сохраняются |
| Расходы за сентябрь → «А доходы?» | Доходы за тот же сентябрь с прежними условиями |
| Несколько расчётов → «К первому сравнению расходов» | Возврат к указанной задаче, затем изменение только нового условия |
| Ошибка на первом запросе → «А по категориям?» | История помогает заново разобрать исходную просьбу; проверка перед расчётом, при неопределённости уточнение |
| Ошибка нового запроса при старом успешном → короткое продолжение | Не переключаться молча на старый расчёт; восстановить смысл или уточнить связь |
| Глобально октябрь, задача сентябрь → «Как в фильтрах сверху» | Текущий UI-период октябрь |

Пример недопустимого поведения: после «за сегодня» вернуть месяц только
потому, что модель забыла period; после «на такси» посчитать все категории;
после ошибки удалить смысл беседы или исполнять невалидные условия.

Согласованные правила реализуются совместно с зависимыми контрактами
извлечения №3 и обмена сообщениями №4 после их отдельных согласований.
Формат сообщений модели, способы повторных вызовов и source schema
этим документом не утверждаются. Текущий путь модели пока не получает
историю и не реализует все эти правила; согласование не является приёмкой AI.
