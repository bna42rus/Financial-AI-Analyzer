# Временная защита picomatch

В CI 17 ноября 2026 года обнаружен GHSA-fc5q-39xc-vjpf: повторяемые
extglob с единственной ветвью `+(*)`, `+(*a)`, `*(*)` допускают ReDoS.
На момент исправления npm публикует 4.0.7, официального исправленного
релиза в advisory нет: https://github.com/advisories/GHSA-fc5q-39xc-vjpf.

`patches/picomatch@4.0.7.patch` добавляет консервативную проверку
единственной нелитеральной ветви к имеющемуся в библиотеке механизму
литерализации опасных повторяемых extglob. Проверка действует также
при `maxExtglobRecursion:false`. Обычные glob, перечисления расширений,
литеральные повторения и используемый Playwright шаблон сохраняются.
Повторяемые extglob с wildcard внутри такой ветви теперь трактуются
буквально. Это намеренное ограничение инструментов разработки;
пользовательский API не предлагает произвольные glob.

`check:dependency-security` сначала проверяет фактически установленную
зависимость обоих приложений, затем запускает полный audit, исключив
только идентификатор этого исправленного локально advisory. Проверка
литерализации падает сразу при отсутствии патча, прежде чем выполнять
длинную строку. Остальные advisories продолжают блокировать CI.

После появления официального исправления: обновить зависимость,
проверить регрессионные случаи, удалить patch, patchedDependencies и
точечное исключение audit. Не удалять проверку уязвимых шаблонов.
