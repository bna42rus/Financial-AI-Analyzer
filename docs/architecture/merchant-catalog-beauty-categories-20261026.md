# Красота и уход: назначения BEA001–BEA056 и правила BEA-U01–BEA-U28

**Статус:** проект на согласование владельцу, 26.10.2026. Это **дополнение к [единому справочнику](./merchant-catalog-master-20261025.md)** (записи BEA001–BEA056) в рабочей ветке PR №53. Отдельный файл выбран потому, что большой мастер-файл перестал корректно возвращаться для безопасного редактирования. Перед реализацией интегрировать правила по стабильным BEA ID, без дублирования.

**Существующие категории:** «Красота и уход → Парикмахерские и салоны», «Косметика и уход», «Прочий уход». Пограничные: «Здоровье и спорт → Врачи», «Образование → Курсы», «Работа и бизнес → Сервисы для работы/Реклама», «Подарки и благотворительность → Подарки», «Жильё и дом → Товары для дома». Это стартовое дерево, не принудительное для пользователей со своими категориями. **Не создавать категории автоматически.**

**Важные инварианты:** доказанный фактический получатель ≠ производитель товара ≠ агрегатор записи; экономическая цель оплаты и финансовая роль проверяются отдельно. Для очевидного обычного профиля специализированного магазина/салона отсутствующий чек **не** создаёт «Стоит проверить». При настоящей неоднозначности допустим обоснованный предварительный профиль + видимый Review; если нет оснований даже для направления — не назначать наугад. Все банковские факты, исходная строка, source/HMAC, дата/сумма/валюта, userVerified, личные правила, split/dedupe и разграничение пользователей неизменны. Нельзя выводить здоровье, диагноз, пол или личные процедуры только из бренда.

## Решения, предложенные на согласование

1. Золотое Яблоко, Лэтуаль, Рив Гош, «Магнит Косметик» и «Улыбка радуги» — обычная категория «Косметика и уход» без лишней пометки за отсутствие чека; доказанный бытовой/детский товар уточняет категорию. Разрешение многопрофильных конфликтов остаётся независимым.
2. Парикмахерские, барбершопы, маникюрные студии — «Парикмахерские и салоны» без Review для очевидной услуги. Подтверждённый курс/товар/франшиза отдельно.
3. Явно эстетическая эпиляция → «Прочий уход», медицинская консультация — только при доказанном виде врачебной услуги. Wax & Go многосервисный; категория может быть предварительной с «Стоит проверить» лишь когда действительно неясно направление.
4. DIKIDI и YCLIENTS — межраздельные платформы записи/CRM, **не** салон/маникюр по названию. Оплата услуги и рабочая подписка не смешиваются.
5. Косметический бренд на упаковке не равен получателю денег, PEND не активировать до доказательств; «Белорусская косметика» — не отдельный merchant.

| BEA-T40 | Повторный импорт одной косметической покупки с тем же банковским источником, затем новая независимая покупка на ту же сумму | Дубликат по существующим правилам не удваивается; новый реальный платёж не склеивается по одному имени/сумме |
| BEA-T41 | Косметическая покупка, оформленный возврат 1000 ₽ и отдельный банковский кэшбэк 50 ₽ | Возврат корректируется по установленной связке, не новый заработок; кэшбэк собственная финансовая семантика |
| BEA-T42 | Подарочный сертификат салона, пополнение/погашение; две записи об одном экономическом расходе | Нет удвоения в аналитике: действующий вид/связи обрабатываются отдельно; не придумывать источник или сумму |
| BEA-T43 | Пользователь вручную подтвердил «Прочие расходы», новый каталог предлагает косметику | Не перезаписывать userVerified; не обучать автоматически всех пользователей на одном ручном исправлении |
| BEA-T44 | У пользователя нет стандартной категории «Парикмахерские и салоны», есть своя «Стрижки» | Назначать только активную совместимую пользовательскую категорию по собственному правилу; не воскрешать удалённый узел |
| BEA-T45 | Перевод частному лицу: скрытый телефон, HMAC совпадает с прошлой оплатой услуги, нет назначения | Не раскрывать телефон, не выводить салон/услугу из HMAC; подтверждённое пользовательское правило применяется лишь в разрешённом объёме |
| BEA-T46 | Модель сообщает 99% уверенности, что «Подружка» означает BEA051 | Guard отклоняет несовместимый merchant match; не доверять уверенности вместо доказательств |
| BEA-T47 | Чужой operation ID, истёкшая revision/preview, попытка переклассифицировать beauty-операции другого пользователя | Сервер отклоняет изменение; не раскрывает чужую финансовую или чувствительную информацию, нет побочных эффектов |
| BEA-T48 | Один синтетический набор покупок/возвратов/частей: Обзор, Операции, Бюджеты, Анализатор | Одинаковые суммы на одинаковом периоде/категориях; parent не удваивается; явные фильтры текста Анализатора приоритетнее глобальных |

## Критерии приемки, параметры и дальнейший порядок

1. **Покрытие списка.** Все BEA001–BEA056 проверяются отдельными синтетическими примерами: полные имена, все предложенные формы, падежи и существенные разделители, отрицательные фразы/подстроки. Девять PEND должны остаться отключёнными до проверки торгового источника, в том числе BEA013 — описание типа магазина, а не единая компания.
2. **Обычные оплаты без чека.** Для однозначной бьюти-сети или барбершопа исходное назначение без category Review. Для многоотраслевых платформ/товарных брендов — не произвольный профиль, а подтверждённый смысл либо неразрешённость. Для Wax & Go предварительная «Прочий уход» + Review допустима только при реальной неоднозначности процедуры.
3. **Разные финансовые роли.** Товар/услуга, предоплата/резерв, выплата мастеру, комиссия, купон/сертификат, кэшбэк, возврат/отмена и покупка в подарок различаются по проверенной финансовой модели. Не удваивать исходный parent, не выдумывать части и связки, не брать один торговый бренд за доказательство конкретного содержимого.
4. **Приватность и доступ.** Не передавать модели настоящие HMAC, сырые счета/телефоны, номера и другие конфиденциальные данные; не выводить из beauty-платежей пол/возраст/диагноз/лечение/состояние или сексуально-интимные подробности; сохранять source/provenance, личные правила и права двух разных пользователей.
5. **Регрессия.** Одни и те же операции на Операциях/Обзоре/Бюджетах/Анализаторе дают согласованные результаты; явные текстовые фильтры Анализатора имеют приоритет; повторный импорт и ручная подтверждённая категория не ломаются. Серверные guard и Analyzer Action Registry не обходятся моделью.
6. **Доказательства.** Фактический PASS объявлять только после запуска исполняемого теста с показанным входом, результатом и версией. Документальная проверка полноты сценариев — не тест модели. Платные вызовы не делать сериями без явной цели, сначала показать пользователю вопросы и ответы.

**Открытые предложения для владельца:** сохранить дефолт «Косметика и уход» для обычной покупки в «Магнит Косметик»/«Улыбка радуги»; эстетическую эпиляцию — в «Прочий уход»; обычные услуги маникюра — в «Парикмахерские и салоны»; multi-service Wax & Go без вида — предварительно «Прочий уход» с Review только при достаточном основании. Если эти правила корректируются, синтетические expected и BEA-U должны быть обновлены **до** реализации.

**Следующий раздел по реестру:** «Связь и интернет»: сначала состав операторов/провайдеров, затем написания, категории и независимые проверки. В этом коммите нет изменений API, БД, сайта или настройки модели.
