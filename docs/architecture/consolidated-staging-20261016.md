## Причина отсутствия загрузки

В установленной версии сохранились ServerImport и весь серверный импорт.
Но `prepare-assistant-staging.sh` запускал обычный build без VITE_API_ORIGIN.
main.tsx выбирает в таком случае демонстрационный App, где импорт не выполняется.
Таким образом, ошибочно опубликован режим демонстрации, а не потеряны ветки.

Staging теперь строится через build-connected-web.mjs с явным адресом API
и Vite mode=staging. Отсутствующий адрес останавливает Staging build.
release.json связывает git SHA, finance/control, connected mode и API origin.
Установщик отвергает demo manifest и несовпадающий SHA/origin. Демонстрационные
Development сценарии и их тесты сохраняются.

Браузерная проверка помощника в CI использует готовый Vite bundle/preview,
проходит вход, контекст/повторы/удаление чата и импорт настоящих синтетических
PDF/CSV/XLSX через file picker, PostgreSQL и runImportStage. Исходные файлы,
имена и реквизиты не должны попадать в HTTP payload. Другие финансовые и
интерфейсные проверки выполняются полной bootstrap suite.

## Обновление уже работающего помощника

prepare-staging-release.sh читает только канонический публичный API origin
из приватной настройки сервера и собирает connected frontend из pinned SHA.
Root update-staging-release.py сверяет runtime source binding с существующей
приватной настройкой модели. При отличающемся API binding обновление запрещено:
не создаётся новый pilot и не обнуляются вызовы/расходы. В этой версии API source
не меняется; изменения относятся к установке, сборке UI, проверкам и документации.

Сохраняются исходные Caddy и Finance instance drop-in. Новый release получает
собранный интерфейс и те же исходники API. После проверки Caddy переключается
только тестовый сайт; Finance запускается с прежним credential и бюджетом.
Control, mail, backend-current, доступ пользователей, миграции и финансовые
данные не меняются.

Если не найден активный CashNeuro import service, устанавливается отдельный
cashneuro-staging-import.service с DynamicUser и scoped finance_api DB URL.
Worker получает только APP_ENV/API_PROFILE/DATABASE_URL. Auth secret, KMS и
AI credential ему не передаются. При наличии другого активного import service
он сохраняется. Код worker уже присутствовал в исходной общей версии.

Rollback восстанавливает прежние API/frontend настройки и состояние добавленного
import service. База, технические квитанции стоимости и приватный ключ не
переписываются. Переключение выполняет GET-проверки и не отправляет model POST.
Ручная проверка опубликованного сайта остаётся отдельным этапом после команды
на сервере; CI не подтверждает состояние удалённого VPS.
