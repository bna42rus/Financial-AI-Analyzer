# Анализатор: первый пакет нового контракта

25 ноября 2026. Основание — [согласованная программа, раздел 16](../../product/analyzer-improvement-program-20261117.md#16-согласованная-переработка-25-ноября-2026-года). Статус: **изолированный контракт, без подключения к рабочему маршруту**. Это первый пакет V2-S1/V2-S2 и начало проверки формы V2-S3, не готовый новый Анализатор.

[Матрица](coverage.json) содержит все 240 задач и 12 диалогов. Для каждой задачи сохранены исходная формулировка, группа, кандидаты инструментов, собственный проверяемый критерий, пробелы и необходимые проверки. Общие входы и требования результата находятся в записи группы. `candidate` означает найденный символ/файл; `missing` — необходимость отдельного инструмента или договорной модели в этом маршруте. Это не доказательство отсутствия любого похожего кода во всём репозитории. Все сценарии пока `mapped_not_accepted`.

Существующий [каталог 337 вопросов](../analyzer-acceptance/questions-v1.json) остаётся отдельным набором проверок Registry; он не заменяет 240 продуктовых задач. Пересечения допускаются, нумерация обоих каталогов сохраняется. Закрытые переформулировки для оценки модели нужно готовить отдельно от примеров для разработки.

## 1. Границы ответственности

| Слой | Получает | Возвращает | Что проверяется далее |
|---|---|---|---|
| Понимание | Вопрос и разрешённая проекция контекста | `Intent` | Структура и сохранение смысла, включая отрицания |
| Подготовка | Intent, серверный контекст, текущие разрешённые справочники | PreparedTask либо адресное уточнение | Права, типы, полнота, ревизии, ограничения инструмента |
| Исполнение | Только PreparedTask | Проверенные факты/состояния шагов | Финансовые инварианты, зависимости, свежесть |
| Представление | Проверенные результаты и выбранный формат | Число/таблица/график/объяснение | Каждая цифра имеет источник; нет внутреннего reasoning |
| Диагностика | Коды стадий и учёт вызовов | Безопасная запись | Нет выписки, паролей, реквизитов и свободного частного текста |

Новый файл [intent.ts](../../../packages/analyzer/src/next/intent.ts) — проверяемая форма намерения. Он не вызывается API, не заменяет семантическую проверку и не исполняет инструменты. Никаких новых версий health, хранилища, fingerprint и текущего `assistant-workflow/7` этот пакет не вводит. `cashneuro-intent-prototype/1` — отдельная версия прототипа, её нельзя записывать как прежний план.

## 2. Общая оболочка намерения

Все поля обязательны, все объекты закрыты, лишние поля запрещены. `action` выбирает ровно один вариант `parameters`; аргументы разных действий не смешиваются.

```ts
Intent = {
  version: 'cashneuro-intent-prototype/1';
  action: 'read' | 'calculate' | 'explain' | 'advise' | 'propose'
        | 'compare' | 'source' | 'interface' | 'clarify' | 'unrelated' | 'report';
  binding: Binding;
  parameters: ParametersForAction;
  presentation: {
    format: 'auto' | 'number' | 'table' | 'chart' | 'operations';
    detail: 'short' | 'normal' | 'detailed';
  };
}
Binding = {mode:'new'}
  | {mode:'continue'; conditions:'merge_ui'|'pin'}
  | {mode:'reference'; handle:Alias; conditions:'pin'}
  | {mode:'answer'; clarification:Alias; option:Alias|null};
Alias = string; // ^[a-z][a-z0-9_]{0,31}$; только из проекции данного запроса
```

Локальные ключи шагов отчёта могут создаваться моделью. Ссылки на историю, варианты, факты и уточнения должны разрешаться сервером по выданной текущему запросу таблице псевдонимов. Совпадение строки не даёт доступа. UUID, ownerId, произвольный SQL, actionId и права не являются аргументами намерения. Имена объектов разрешаются по личному каталогу; одинаковые имена требуют выбора с родителем/путём.

| Действие | Точные параметры прототипа | Следующая серверная проверка |
|---|---|---|
| `read` | `metric`, `grouping`, `comparison`: допустимое значение текущего Registry либо `null`; `conditions`: список `{field, op:'set', expression}` или `{field, op:'clear'|'use_current'}`; `options`: существующая закрытая `AnalysisOptions` | null означает наследование, а для новой задачи — необходимость определить значение; expression разбирается по конкретному полю, не как SQL. Неизвестное существенное условие не отбрасывается |
| `calculate` | `calculator`: один вид существующего калькулятора; `edits`: список `{field, op:'set', value, quote}` или `{field, op:'clear'}`. Тип value взят из схемы именно этого калькулятора | Одна правка поля; quote соответствует текущему сообщению. Сохранённые поля берёт сервер. Затем полнота, денежный разбор, даты/единицы, доменные ограничения |
| `compare` | `scenarios`: 2–6 разных Alias; `criterion`: interest / total_paid / payment / net_return / value; `objective`: min / max | Сервер разрешает проверенные сценарии, совместимость суммы, срока, базы и единиц; считает разницу. Другая база сравнения требует отдельного контракта, не произвольной формулы |
| `explain` | `subject:{kind:'concept',question}` либо `{kind:'result',handle}` | Объяснение результата использует только доступные факты; вопрос о понятии не закрывает ожидающий расчёт |
| `advise` | `goal`, `constraints:string[]`, `evidence:Alias[]` | Личный совет требует проверенных личных фактов; численная экономия считается инструментом, не моделью |
| `propose` | Существующий `AssistantChange` по закрытой схеме | Имя → принадлежащий объект; фиксированная выборка; существующие preview/commit/Undo. Нет автоматического сохранения |
| `source` | Существующий `FinancialSourceRequest` | Разрешённый официальный источник, дата и применимость. Ошибка источника не разрешает выдать память за актуальные сведения |
| `interface` | `command:string` | Только конечный существующий `interfaceAction`; неизвестная команда не открывает URL и не исполняет код |
| `clarify` | `question`, непустой `missing:string[]` | Поля проверяются относительно подготовленной задачи; не повторять известные сведения |
| `unrelated` | `message:string` | Никаких финансовых чтений, web и дальнейшего исполнения; финансовая граница проверяется до доступа |
| `report` | 1–12 шагов `{key,after:Alias[],intent:SimpleIntent,bindings:{field,step,fact}[]}` | Без вложенных report. Уникальные ключи и назначения; DAG без циклов; связи только с declared prerequisite; тип/единица факта совместимы с полем назначения |

Ограничения прототипа: текст до 1000 символов, не более 32 правок, 12 шагов, 20 связей на шаг. Превышение не обрезается молча: подготовка предлагает разделить задачу, сохраняя её смысл. Предел 12 шагов — техническая граница пилота, не сокращение продуктового каталога. `null`, `0`, пустой список и отсутствие значения различаются.

`clear` обязательного поля делает задачу неполной, а не подставляет ноль. Для массивов досрочек/смен ставки `set` заменяет весь согласованный массив: добавление/удаление отдельного события должно сначала разрешиться по его конкретному месяцу на сервере. Конфликт с существующим месяцем требует адресного решения. Это ещё не реализованный адаптер свободной речи.

Бюджеты, история, части, связи, договорные кредитки и отдельные сценарии из матрицы пока не получают выдуманные варианты параметров. Они требуют собственных закрытых контрактов/адаптеров до подключения. Схема прототипа не означает, что все 240 задач уже можно исполнить через неё.

## 3. Подготовленная задача и результат инструмента

Следующий этап должен реализовать серверные типы ниже. Модель не создаёт эти объекты.

```ts
PreparedTask = {
  version: 'cashneuro-prepared-prototype/1';
  requestId: string; taskId: string; conditionRevision: number;
  scope: {ownerId:string; chatId:string; chatEpoch:string; generation:string};
  accessRevision: string; dataRevision: string; calendar: {date:string; timezone:string};
  tool: {name:string; version:string}; // из конечной серверной таблицы
  input: ResolvedInputForTool; // принадлежащие ID; деньги целыми строками
  origins: Record<string, Origin>; assumptions: Assumption[];
  dependencies: {taskId:string; fact:string; field:string; unit:string}[];
  effect: 'none'|'preview'; // Intent не даёт права commit
};
Origin = {source:'message'|'task'|'ui'|'policy'; sourceRef:string; revision:string};
Assumption = {code:string; field:string; value:unknown; reason:string};
Fact = {key:string; value:string; unit:'minor'|'count'|'bps'|'text'; sourceStep:string};
Outcome =
  | {status:'completed'; facts:Fact[]; payload:ToolPayload; warnings:Warning[]}
  | {status:'waiting'; missing:MissingField[]; options:Choice[]}
  | {status:'partial'; steps:StepOutcome[]; facts:Fact[]; warnings:Warning[]}
  | {status:'failed'|'interrupted'; code:string; retry:'safe'|'lookup_required'|'none'};
```

`ResolvedInputForTool`, ToolPayload и validators обязаны быть закрытыми отдельными вариантами, не `Record<string,unknown>` для исполнения. Существующие Query/CalculatorInput/AssistantProposal/BudgetReadResult/FinancialSourcesResult — кандидаты адаптеров, не взаимозаменяемые DTO. `unknown` у Assumption допустим только как отображаемое, не исполняемое значение и должен соответствовать конкретному полю. Ошибка проверки не даёт успешных фактов. `waiting` — не успешный расчёт.

| Инструмент/адаптер | Вход → результат | Эффект, проверка, кеш |
|---|---|---|
| Аналитика операций | Query и серверная область → существующий ответ, сумма/count/группы и основание выборки | Только чтение; единое ядро, возвраты/части/свои переводы; кеш по scope+dataRevision+нормализованный запрос+календарь |
| Анализ/статистика | Разрешённая выборка и AnalysisOptions → статистика/сравнение/кандидаты регулярности | Только чтение; знаменатели и неполнота; тот же ключ данных |
| Калькуляторы | Полный CalculatorInput → существующий CalculatorResult, полный график | Без БД и побочных эффектов; точные деньги, нулевая ставка, последний платёж, сумма графика; кеш по версии ядра и каноническим параметрам |
| Отчёт/совет | DAG задач и типизированные связи фактов → проверенные секции и вычисленный вывод | Частичные независимые чтения остаются; зависимый шаг не исполняется после ошибки источника; кеш только если все зависимости пригодны |
| Бюджеты | Разрешённые ID/дата/база → BudgetReadResult | Только чтение; лимит/ревизия/период; отдельно от расчётного предложения создать бюджет |
| Изменение | AssistantChange, фиксированная выборка, актуальные версии → AssistantProposal и существующий preview | Авторизация перед preview и commit; явное подтверждение; существующий idempotency key, атомарность и history/Undo; preview не кешируется для повторного commit без проверки |
| История/Undo | Принадлежащее действие и ожидаемая ревизия → outcome существующего механизма | Отдельная авторизация; допустимость отката, конфликты и прежние связи; не выбирать действие только по последнему тексту |
| Внешние сведения | FinancialSourceRequest → проверенные источники и факты | Финансовая релевантность, allowlist, свежесть; кеш по виду/дате/источнику и сроку актуальности |
| Интерфейс | Finite InterfaceAction → результат устройства | Без финансового чтения; серверные действия не имитируются клиентом |
| Новые договорные инструменты | Отдельные известные условия договора → закрытый результат | Пока пробел матрицы; неизвестная банковская методика не подменяется общим кредитом |

Повторный запрос того же завершённого расчёта не вызывает модель только ради повторного отображения. Перед выдачей личного кеша проверяется доступ; смена пользователя, generation, entitlement, удаление чата и данных инвалидируют соответствующее состояние. Прошлое число остаётся историческим, новый read пересчитывается по текущей ревизии. Расчётный поток не доказывает остаток на счёте.

## 4. Состояния и переходы контекста

Сервер хранит точные входы и проверенные результаты, происхождение полей, варианты сравнения, активную задачу, ожидающее уточнение и историю. Область включает owner/chat/chatEpoch/generation. Текстовое резюме модели не заменяет это состояние.

| Событие | Из какого состояния | Переход и сохраняемые данные |
|---|---|---|
| Новый самостоятельный read | Любое | Прежняя задача в историю; новая область из текущих общих фильтров плюс явный текст |
| Новый калькулятор | Любое | Прежняя задача в историю; никаких случайных фильтров операций |
| Продолжение | completed/partial/waiting | Выбрать ближайшую совместимую задачу; перенести её параметры; обновить только затронутые поля UI; затем явные правки сообщения |
| «С теми же условиями» | completed/partial/waiting | Закрепить прежние условия; UI их не заменяет; явная новая правка побеждает |
| Историческая ссылка | Любое | Разрешить конкретный совместимый снимок; закрепить условия, но заново проверить доступ и текущие данные |
| Ответ на уточнение | waiting | Связать с точным pending и опцией; добавить ответ, сохранить известное; если достаточно — выполнять |
| Вопрос о понятии | completed/partial/waiting | Ответить; активный расчёт, варианты и pending остаются доступными |
| Неоднозначный выбор | Любое | Один адресный вопрос с конкретными вариантами; не выбирать наугад |
| Запуск/завершение | prepared/running | running → completed только после проверки результата |
| Независимый шаг не удался | running report | partial с проверенными успешными чтениями; зависимые шаги блокируются |
| Отмена/потеря связи | running | interrupted либо lookup_required; не считать неизвестный commit откатом |
| Ошибка | running/preparing | failed; не записывать успешный расчёт и не создавать бессрочное уточнение |
| Поздний ответ | Любое | При несовпадении request/task/conditionRevision показать только у исходного сообщения, не менять активную новую задачу |
| Чужой чат/новый аккаунт | Любое | Старые ссылки не разрешаются; приватный кеш очищается |

Приоритет для read: исходная область (текущий UI для new, выбранная задача для continuation/reference) → изменённые после снимка UI-поля при `merge_ui` → явные условия сообщения. Сравниваются значения **и отметки touched**, чтобы изменение UI обратно к исходному значению не потерялось. `use_current` берёт ровно указанное поле UI; `clear` снимает ровно его. Противоречивые повторные изменения одного поля не разрешены.

Приоритет для калькулятора: выбранный сценарий → явные изменения. UI-фильтры операций не участвуют. Смена типа платежа не сбрасывает сумму, ставку, срок и согласованные досрочки. Несовместимый срок, оставляющий событие вне графика, требует решения, а не удаления события. Два равноправных сценария не сливаются молча.

## 5. Допущения и эталоны первых цепочек

| Ситуация | Подготовка и ожидаемый результат |
|---|---|
| Кредит: известны сумма/ставка/срок, тип не выбран | Два сценария с общими условиями; не обязательный вопрос о типе |
| Досрочки/изменения ставки не упомянуты в новом обычном кредите | Пустые списки; допущение доступно в «Как рассчитано» |
| Неизвестны сумма/ставка/срок | Назвать только недостающие существенные поля; не подставлять ставку из памяти |
| Неизвестна стратегия указанной досрочки | Уточнить либо по явной просьбе сравнить обе; не скрывать выбор |
| Вклад без указания капитализации | Адресное уточнение или два явно помеченных варианта; не угадывать |
| Цель без доходности | Сценарий без процентов возможен только как явное допущение; не обещать инвестиционный доход |
| Нет известного остатка | Поток показать можно; доступность покупки и дата дефицита не объявляются точными |
| Данных нет/покрытие неполное | Пустая выборка отличается от нулевого расхода при полной истории |

Эталон расходов: «октябрь 2025» → «по категориям» → «а сентябрь?» → «сравни эти месяцы: где рост?». Год 2025, смысл расходов и прочая область сохраняются. Сентябрь и октябрь сравниваются отдельно; наибольший прирост определяется по знаковой разнице категорий, а не по самой большой категории октября. При двух подходящих парах периодов нужен выбор.

Эталон кредита: «120000 ₽, 12% годовых, 12 месяцев» → «в чём разница и где узнать тип?» → «дифференцированный» → «а ануитентный» → «теперь ставка 25% для обоих» → «что выгоднее?» → «график платежей и процентов». Объяснение сохраняет условия; выбор запускает расчёт. Ставка меняется у обоих вариантов; сумма и срок прежние. Выгоднее по переплате — численный вывод с разницей и первым/последним платежом. График показывает платежи, основной долг и проценты по всем месяцам; линия остатка долга не подменяет этот ответ.

Независимый денежный эталон дифференцированного кредита 120000 ₽ / 12% / 12 мес.: тело 10000 ₽ ежемесячно, проценты 1200, 1100, …, 100 ₽; первый платёж 11200 ₽, последний 10100 ₽, проценты всего 7800 ₽, выплаты 127800 ₽. Эталон 0%: 12 платежей по 10000 ₽, процентов нет. Эти эталоны проверяют существующее ядро; они не доказывают понимание свободной речи моделью.

## 6. Ответ, ресурсы и следующий пакет

У обычного ответа по операциям только «Как рассчитано» и «Открыть в Операциях». Табличная пагинация и явное подтверждение запрошенного изменения — отдельные элементы. Внутренние ссылки, h4/h5, версия модели и лишняя фраза об экономии 0 ₽ без досрочек не показываются. Статусы ошибки понятны пользователю; технический код доступен диагностике.

Цели маршрута: 0 вызовов для полностью распознанных безопасных локальных запросов, обычно 1 для свободной речи, 1–2 для сложного совета. Это не повод отключать независимую проверку смысла до закрытой оценки качества. ## 7. Второй пакет: подготовка и контекст, без интеграции

[Реализация tasks.ts](../../../packages/analyzer/src/next/tasks.ts) разделяет `prepareTask`, `executeTask`, `finishTask`. State и Environment — доверенные серверные значения в памяти, **не схема получения состояния от клиента и не готовый формат хранения**. Подключение к API, миграция истории, durable idempotency и проверка семантики реальной модели остаются отдельными этапами.

- Read использует существующие `resolveTaskDecision`, `parseTool`, разбор дат/денег и фиксированную границу ID. Изменения UI объединяются по полям и touched-ревизиям; `pin` закрепляет условия, сохраняя проверку ревизии и актуальную границу выборки. Голый месяц наследует год выбранного периода; относительные даты используют текущий календарь. При нескольких годах нужен явный год.
- Loan сохраняет неполные условия в pending, спрашивает только недостающие существенные поля и использует существующий `parseCalculatorInput`/`calculateFinancial`. Объяснение оставляет pending и активную задачу. Не выбранный тип даёт два варианта; явный `clear payment` означает снять выбор и снова показать оба. Нулевая ставка не теряется; несовместимый новый срок не удаляет досрочки.
- Compare по кредитам пересчитывает выбранные проверенные входы, считает точные разницы и сохраняет сравнение для объяснения. Одинаковые поля можно продолжать; разные сроки/ставки/досрочки требуют выбора поля или конкретного варианта. Выбор первого варианта по умолчанию запрещён.
- Compare с `criterion:value` пока принимает ровно два read с одинаковыми metric/grouping/остальными условиями. Порядок: первый — база, второй — сравниваемый период. Подготавливается свежий Query с `comparison:custom`, который исполняет общий финансовый адаптер; прошлые totals не переиспользуются. `objective` не обрезает строки результата. Сравнение произвольных разных областей остаётся задачей будущего report-адаптера.
- Read-адаптер получает полный Query, включая options, и обязан применять их общей логикой аналитики; возвращает WidgetResult из общего ядра. Тестовый адаптер покрывает сумму/категории/периоды. Это не приёмка всех статистических/временных опций. Форма подлинного графика в интерфейсе ещё не подключена: прототип возвращает полный существующий график и выбранное представление.
- `guard` обязателен, permissive default отсутствует. Будущий DB-адаптер обязан проверять доступ/ревизии и читать согласованный снимок данных. Pure-функция сама не доказывает права. CAS завершения проверяет request/revision/scope и ревизии данных/доступа: поздний ответ не меняет активную новую задачу; ошибка не регистрирует успешную задачу.
- Проекция для понимания содержит псевдонимы, параметры гипотетического кредита и краткие признаки read. Owner/account/category/operation UUID и банковские идентификаторы не передаются. Перед выдачей проекции API обязан проверить доступ; прототип пока не имеет API.

Для нового разбора read реализованы literal-адаптеры периода/проводки, порога суммы, точного имени личной категории/счёта/контрагента и магазина. Остальные условия, неоднозначные имена, несовместимые сравнения и не входящие в пилот действия останавливаются явно. Неподдержанный параметр не отбрасывается, никакая мутация не выполняется. `quote` проверяет наличие основания в текущем сообщении; это не доказательство семантической эквивалентности значения. Независимая проверка смысла ещё нужна.

Они проверяют уже заданные намерения, общий денежный эталон, сохранение условий, уточнения, границы чатов/выборки, ошибки и поздние результаты. Свободное распознавание опечаток моделью этим не доказано: тест подаёт ожидаемое намерение для фразы с опечаткой.

## 8. Третий пакет: сквозной офлайн-проход

[workflow.ts](../../../packages/analyzer/src/next/workflow.ts) связывает разрешённую проекцию контекста → `Provider.understand` → закрытый разбор ответа → обязательный `Services.review` → подготовку → финансовый адаптер → CAS завершения. `PrototypeSession` остаётся изолированным модулем в памяти; действующий API его не импортирует.

Провайдер получает только version/question/date/context. Вопрос проходит существующий privacy guard; проекция не содержит UUID владельца, операций, счетов и категорий, банковские строки или полный каталог. Авторизация обязательна перед выдачей проекции, исполнением и повторной выдачей результата. Структурированный ответ содержит relevance и intent; ambiguous/unrelated не запускают финансовые инструменты. Противоречивые поля и лишние команды отклоняются. Review обязателен без разрешающего значения по умолчанию. В тестах это поддельный callback, а не реальная независимая проверка понимания языка.

Повтор с тем же requestId и телом разделяет уже выполняющийся Promise либо возвращает копию завершённого результата. Новый вызов понимания и повторное финансовое чтение не выполняются. Другое тело с прежним requestId отклоняется. Старый ответ при изменившейся ревизии данных помечается историческим; повтор не активирует старую задачу поверх новой. Проверка доступа при повторе сохраняется. Кеш ограничен 100 запросами на сессию; при заполнении новые вызовы не запускаются.

Поздний результат понимания или review отбрасывается до подготовки, если уже поступил новый вопрос. При выполнении инструмента действуют request/revision/scope и проверки доступа/данных. Само объяснение не отменяет уже выполняющийся расчёт. Новый финансовый вопрос может его вытеснить. После изменения данных во время понимания read готовится на текущую ревизию, а не на скопированный старый итог. Внутреннее состояние и тексты исключений не возвращаются как диагностика; используются ограниченные коды стадии.

18 новых тестов прогоняют две цепочки через поддельный провайдер и проверяют повторные запросы, конкурентность, позднее понимание/review/инструменты, отзыв доступа, смену generation, свежие данные, privacy, ошибки и изоляцию копий. Ответы и намерения в этих тестах заданы заранее. Это доказательство связности программного маршрута, **не измерение качества реальной модели** и не приёмка всех 240 задач. Тестовые callback-вызовы не являются платными модельными запросами.

```bash
node --test packages/analyzer/test/next-workflow.test.ts
```

Следующий этап — подготовить небольшой изолированный пилот реального понимания: проекция/промпт, отдельные переформулировки, проверка смысла и бюджетные измерения. До платного подключения нужны существующие durable journal/reservation/settlement, сетевые deadlines и обработка неизвестного исхода. Этот модуль не реализует транспорт модели, тарификацию, миграцию истории или серверное хранение идемпотентности. Его transient fingerprint не заменяет keyed fingerprint существующего журнала. Платных вызовов, изменений бюджета и обновления сайта в третьем пакете нет.

## 10. Разбор первого реального прогона: формат периода

В прогоне `fd60937f09a1b13f654229dc51f8de7f99303d34` прошли пять кредитных реплик. `read-new` был отклонён, две зависимые реплики пропущены; стоимость шести вызовов — 0,507145460 ₽, неизвестных резервов нет. Сохранённый ответ содержит правильные `expenses`, `category` и период `2025-10`. Причина отказа — требование дословной цитаты «октябрь 2025» в literal-адаптере, а не неверный выбор смысла этого запроса. Это наблюдение одного прогона, не текущий баланс или приёмка всего Анализатора.

[period.ts](../../../packages/analyzer/src/next/period.ts) принимает именованный период либо канонические месяц/день/интервал. Для канонического значения сервер независимо разбирает исходный вопрос прежней грамматикой и требует совпадения границ. Максимальные исходные фрагменты не позволяют отбросить явно заданный год или сузить диапазон до удобной даты. Префикс месяца внутри ISO-дня не становится доказательством целого месяца. Неоднозначность, отсутствующее основание, неверный год и невозможные даты отклоняются. Короткий месяц сохраняет однозначный год предыдущей задачи; относительные даты используют текущий календарь. Старый task-literals/1 и семантический oracle не ослаблены.

Добавлены отрицательные случаи и точный синтетический payload отклонённого `read-new`; он теперь проходит подготовку и общий расчёт с ожидаемыми 16800 коп. Изменение не требует нового ответа модели на этот вопрос. Входной prompt и schema пилота сохранены, чтобы fingerprint уже оплаченных ответов оставался прежним.

Wrapper принимает `--resume <предыдущий SHA>`: новая версия кода работает с прежними закрытыми run.json/журналом и request IDs. Все прежние проверки account binding, fingerprints, доставленного usage и бюджета сохраняются. Уже полученные ответы читаются из журнала; новые вызовы возможны только для ранее пропущенных реплик. При несовместимом prompt/schema или неизвестном исходе повтор блокируется. Ни журнал, ни расходы не копируются в пустой новый бюджет. Результат оставшихся двух реальных вопросов ещё требуется получить на сервере.


## 11. Разбор второго прогона: короткое продолжение ошибочно объявлено новым

После исправления периода `read-new` прошёл из сохранённого ответа. В `read-month` модель вернула правильные `expenses/category`, `comparison:none` и `2025-09-01/2025-09-30`, но указала `binding:new` для «А сентябрь?». Новый независимый read не наследовал год/область предыдущего расчёта; проверка отклонила его. Это другая причина, чем формат `2025-10`. Повторный прогон использовал шесть прежних ответов и сделал один новый; сравнение месяцев ещё не запускалось.

[read-binding.ts](../../../packages/analyzer/src/next/read-binding.ts) восстанавливает продолжение только при активном успешном read, без ожидающего уточнения/выполняющейся задачи, и единственном set-условии. После удаления разговорной связки весь текст должен распознаваться одним закрытым literal-адаптером: период, порог суммы или точное имя из разрешённого серверного справочника. Для магазина допустимы только известные имена последнего соответствующего результата/фильтра. Произвольный текст не становится доказательством имени. Это правило структуры запроса, а не список названий месяцев или конкретных тестовых фраз.

Период проверяется относительно предыдущего контекста, сумма — с сохранением строгости границ, имя — с сохранением смысла/исходного написания. Затем именно исходное условие применяется поверх обычного объединения UI-полей. Не запрошенные текущей репликой metric/grouping/comparison/statistics берутся из серверной задачи; скопированные моделью defaults не сбрасывают их. Значение даты/суммы, противоречащее источнику, отклоняется, а не превращается в новый запрос.

Полноценные самостоятельные вопросы, явные reference/answer/continue, новая тема, отрицания, несколько условий, отсутствие совместимого активного read и pending/running не переписываются этим восстановлением. Чужой чат/владелец/generation по-прежнему блокируются до разрешения контекста. Дополнительного вызова модели нет. Правила остальных произвольных связей и поддержка полного каталога этим не объявлены завершёнными.

Сохранённый синтетический payload `read-month` проходит прежний oracle и общий расчёт с итогом 12000 коп. Добавлены восемь проверок нормализации, независимых запросов, конфликтующих значений и приоритета UI. Prompt/schema пилота сохранены: `--resume fd60937f09a1b13f654229dc51f8de7f99303d34` переиспользует семь полученных ответов; новый вызов требуется только для оставшегося сравнения.

Пилот теперь печатает разрешённый вид связи (`resolved`) и при отказе — код подготовки/несовпадения и проверенные поля read/compare. Это диагностика фиксированного синтетического набора; значения проходят общий privacy sanitizer. Ключи, URL БД, реальные строки операций и серверное состояние в этот вывод не входят. Фактический результат последнего реального вопроса ещё требуется получить.
