## Параметризация DIG-P01–P10

1. **DIG-P01 — профили:** все 97 ID обязательны, с проверкой допустимого профильного назначения и границ. Три PEND дают положительную проверку сохранения запрета, не положительную активацию. Каждая ссылка на NET/TEL/другой DIG остаётся ссылкой.
2. **DIG-P02 — формы:** весь инвентарь 762 кандидатов, раздельный oracle для positive/conditional/negative/blocked в контексте. Полноту и число форм считать по тем же NFKC/casefold/ё-е правилам инвентаря, не выдавать повторы регистра за новые aliases. Не все искусственные формы подтверждены выпиской.
3. **DIG-P03 — контекст:** допустимая форма в начале/середине/конце безопасной строки, пунктуация и технические пробелы; обычная речь/чужое слово/число/другой продукт/посредник. Пробел/дефис и похожие буквы меняются только в согласованных границах.
4. **DIG-P04 — предмет и цель:** каждое семейство услуги/пакета, известная и неизвестная личная/рабочая цель, явное personal rule, установленная непрограммная услуга. Очевидная базовая категория не требует лишних уточнений; настоящая неоднозначность получает причину.
5. **DIG-P05 — финансовый смысл:** purchase/refund/fee/transfer/balance/payout и расход/доход/neutral/unresolved/mixed по достаточным основаниям, а не полный бессмысленный Cartesian product. Отдельные kind/role/category/link/dedupe confidences; источник и причина независимы от уверенности модели.
6. **DIG-P06 — пользовательское дерево:** expense/income/both, rename/hide/delete, родитель без leaf, отсутствующий узел, личные правила/подтверждение/parts, собственные и чужие ID. Никакого молчаливого создания/восстановления/переноса истории.
7. **DIG-P07 — жизненный цикл:** первый импорт, повтор, исправление, новый независимый платёж, частичный возврат, отмена/ошибка/повтор запроса без неопределённого двойного commit. Идентичности/parent/links берутся из фактического сценария, не из golden при провале предыдущего хода.
8. **DIG-P08 — время и суммы:** integer minor units, несколько валют, operation/posted/source даты, граница суток/месяца в зонах пользователя восточнее и западнее UTC, годовая и месячная оплата. Отдельные периоды и режимы gross/net по продуктовой модели; не фиксировать всем Москву.
9. **DIG-P09 — каналы результата:** импорт, допустимое ручное действие/preview/commit, модели/cache/closed Registry, операции/обзор/категории/графики/бюджеты/Analyzer. Для недоступного пути фиксировать BLOCKED с причиной, не PASS по сходству другого экрана.
10. **DIG-P10 — происхождение и воспроизводимость:** только synthetic fixtures, версия каталога/схемы/правил/Registry, источник ответа и cache, неизменённый raw модели, решение валидатора/приложения, фактический parent и reason. При будущем live-прогоне отдельные новые POST/архивный replay/расход/остаток общего разрешённого лимита и отсутствие неизвестного автоматического retry. Согласование этого документа само по себе не обновляет истёкший runtime admission и не обнуляет старый расход.

## Как впоследствии принимать результаты

- Для каждого параметризованного случая сохранять **expected / actual**, product/merchant identity, category path и собственный ID, role/kind, review flag и понятную причину, source/confidence/verification, raw response/validator outcome, components/links/totals и фактический parent, где применимо. Поля неприменимого facet отмечать явно, а не требовать выдуманных значений.
- Разделять **PASS / FAIL / BLOCKED / NOT_RUN**. Дополнительно разделять причину: модель, схема/парсер, evidence guard, compiler, финансовый учёт, UI, права/источник, неверный oracle. Невыполненный/PEND/недоступный сценарий не считать принятым продуктовым поведением.
- Отказ приложения на ошибочный ответ модели может быть PASS проверки защитного отказа и одновременно FAIL семантики модели. Исходный неверный ответ не переписывать и не выдавать за правильный ответ модели. Пример исторического чужого назначения Яндекс Go → Топливо не становится корректным после guard.
- Наличие правильного количества строк не доказывает надёжность. Нужны отсутствие ложных слияний/потери денег/перезаписи пользовательских данных, объяснимая неопределённость и полное покрытие инвентаря с его статусами. Ограниченное число свежих ответов модели не объявляется доказательством точности на всех формах.
- Нынешняя проверка документа: уникальность/непрерывность ID C/T/P, полнота ссылок, соответствие инвентарю 97/762 и 62/32/3, отсутствие изменений runtime и корректность Markdown diff. Это **не выполнение DIG-T01–T64**.
