### Статусы и пределы подтверждения

- **SRC — 57:** Прямо прочитана первичная страница в описанном объёме; иногда доступен только ограниченный профиль/заголовок. Не все банковские строки/получатели/филиалы.
- **IDX — 30:** Первичная собственная страница/отчёт/справка прочитаны через индексированный текст; для Авроры — первичный список партнёров аэропорта, Nordwind — карточка участника IATA, московских автовокзалов — городская страница объектов. Они подтверждают указанный профиль/identity, не все текущие продажи/получателей/маршруты. Дата индекса может быть старше просмотра.
- **REF — 1:** TRV019 Аэроэкспресс ссылается на согласованный R11, его явные формы переиспользованы без потерь; первичная страница также прочитана сейчас. Это не новая merchant identity.
- **HIST — 1:** TRV015 Ангара: текущий домен перенаправляет на i8fly.ru/И8/вертолётный профиль. Это не доказательство текущих регулярных перелётов под прежним именем/правопреемства. Новая глобальная авиа-активация BLOCKED до отдельного источника; доказанные исторические source-факты сохраняются.

Просмотр/попытки первичных источников — **27.10.2026**, не дата публикации/проверка всех юридических полномочий. Варианты написания — наши явные кандидаты для будущей проверки, не цитаты источников и не реальные выписки. Старые PEND MP/EDU и ограничения FASH/прочих разделов сохраняются. ### Единые правила TRV

**TRV-U01 — Приоритет решений.** Ручной facet операции → конкретное личное правило → широкое личное правило → глобальный каталог → AI → допустимый банковский facet. Оплата обычной установленной профильной услуги не требует чека каждого компонента. Известный иной предмет/цель/личное решение выше общего бренда. Каталог не меняет source/vendor/сумму/дату/role/links/части.

**TRV-U02 — Обычный перелёт.** Установленный обычный платёж за авиаперелёт → Авиабилеты без Review только из-за отсутствия номера рейса/маршрута/детального тарифа. Общая неразделённая стоимость билета с его обычными сборами/багажом/местом остаётся одним расходом; из неё не угадывать доли. Отдельно доказанные ресторан, отель, страховка, магазин, корпоративный расчёт имеют свой предмет/роль.

**TRV-U03 — Авиа-группа не получатель.** Аэрофлот/Россия/Победа и прочие перевозчики не объединяются по владельцу/коду рейса. SU/DP/S7/N4/код аэропорта/терминал не независимые глобальные aliases. Платёж агенту не меняется на авиакомпанию, даже если известен рейс. Аэропортовый сбор в составе билета не второй расход аэропорту.

**TRV-U04 — Железная дорога.** Доказанный дальний/междугородний ж/д билет → Ж/д билеты; городской/пригородный проезд/электричка → прежний Общественный транспорт. Сапсан/Ласточка/Таврия — названия продуктов/поездов, сами по себе не merchant и не всегда один вид сообщения. ФПК/РЖД могут иметь другие платежи, выплаты и продукты.

**TRV-U05 — Аэроэкспресс и аэропорт.** Обычный установленный аэропортовый проезд Аэроэкспрессом сохраняет R11/Общественный транспорт. Частный такси-трансфер обычно Такси; городской автобус/парковка/отель при аэропорте по своему предмету. Само слово аэропорт, страна/город получателя или дальность от дома не переносит все операции в Путешествия.

**TRV-U06 — Междугородний автобус.** Установленный междугородний/международный автобус → Другой междугородний транспорт, городской/пригородный → Общественный транспорт. Название автовокзала — объект/канал, не гарантированный получатель или перевозчик; кафе/багаж/штраф/камера хранения не билет автоматически. Рейсы/границы/расписания каталог не удостоверяет.

**TRV-U07 — Вода и круиз.** Обычный установленный туристский круиз/пакет → Туры; водный билет перевозки между городами → Другой междугородний транспорт. Короткая досуговая прогулка → подходящий ENT-досуг, регулярный городской водный проезд → прежний транспорт. Название судна/причала/площадки не доказывает оператора или длительность программы.

**TRV-U08 — Предмет агрегатора.** Туту/OneTwoTrip/Яндекс Путешествия/Ozon Travel/Agent.ru и другие широкие сервисы не получают один лист всем оплатам. Известный авиа/жд/автобус/отель/тур → свой путь. Когда надёжно известно только путешествие, допустим существующий родитель Путешествия без Review исключительно за неизвестный лист. Если реально спорны назначение/identity/роль — предварительный подходящий узел с объяснимой причиной; не угадывать маршрут/состав.

**TRV-U09 — Aviasales: две модели.** Собственная справка подтверждает прямые Билеты от Авиасейлс и сторонних продавцов. Поэтому нельзя закрепить ни всегда только поиск, ни всегда продавец. Source merchant/доказанный агент/перевозчик сохраняются раздельно; использование поисковой страницы не расход. Не открывать клиентский профиль/почту/билет для справочника и не просить booking code ради ясной категории.

**TRV-U10 — Туроператор и агент.** Обычный установленный турпакет → Туры, без запроса состава всего пакета. Отдельно известный отель/билет/экскурсия/страховка/другая услуга по своему предмету. Туроператор, турагент/франчайзи/продавец, платёжный агент и фактические поставщики не одно лицо; лицензии/реестры/финансовые гарантии каждого продавца здесь не сертифицируются.

**TRV-U11 — Отели и краткосрочное размещение.** Обычная установленная оплата гостиницы/хостела/краткосрочных апартаментов → Отели без Review только за отсутствие брони/номера комнаты/чека. Наименование апартаменты/квартира не автоматически Жильё → Аренда: доказанное длительное проживание/аренда жилья по прежнему HOME. Нет правила угадывать срок по сумме/городу/получателю.

**TRV-U12 — Отель не все услуги.** Отдельно установленные ресторан/бар/SPA/фитнес/банкет/коворкинг/парковка/магазин/медицинская услуга получают своё направление. Проживание с включённым завтраком не автоматически две операции. Название санаторий/оздоровительный не диагноз/лечение; сложный пакет без долей не раскладывать искусственно.

**TRV-U13 — Объект и гостиничный бренд.** Сеть/управляющая компания/девелопер не один собственник-получатель всех отелей. Конкретный московский Метрополь/Националь/Балчуг/Four Seasons не все одноимённые гостиницы мира. Смена вывески/домена/международной франшизы не переписывает исторический merchant и не доказывает текущее юрлицо.

**TRV-U14 — Экскурсии и походы.** Многодневный/пакетный туристский продукт/организованный поход → Туры. Отдельная экскурсия/аудиогид/входной билет в доказанном контексте поездки → Расходы в поездке, обычный местный досуг → подходящая ENT-категория. Площадка и гид/организатор различимы; спортивное снаряжение/учебный курс не тур от слова поход.

**TRV-U15 — Аренда авто и трансферы.** Обычный прокат RentMotors/RexRent → существующий Транспорт → Прочий транспорт, не Каршеринг по слову аренда. Заказной пассажирский такси-трансфер → Такси; доказанный иной предмет по нему. Явная личная категория/правило на расходы конкретной поездки выше; один расход не считается одновременно и Такси/прокатом, и travel-категорией.

**TRV-U16 — Подписка, поддержка и сервисный сбор.** Отдельная плата за помощь/членство/приоритет/доступ/корпоративную платформу/отмену/обмен не автоматически стоимость нового перелёта/отеля. Установленный сбор неразрывного заказа можно учитывать с соответствующим предметом по действующей модели/личному решению; отдельные факты не создавать из одной строки. Возвратный сбор/штраф не автоматически государственный штраф.

**TRV-U17 — Предоплата и остаток.** Два реальных списания за предоплату/остаток могут быть разными частями оплаты одного заказа, но не дубликаты от одинакового merchant. Банковская операция и бронь/итоговая цена в письме не два новых расхода. Учёт фактически оплаченного/предоплаты по действующей модели; срок поездки/заселения не переносит деньги на другой месяц.

**TRV-U18 — Холд, депозит и залог.** Авторизация/холд без учтённого списания не создаёт posted expense. Реальное списание обеспечительного депозита, его возврат, удержанная часть и обычная услуга требуют своего source/role/links; не объявлять все суммы со словом залог neutral или расходом. Если смысл реально не установлен, сохранить unresolved/Review по контракту. Условия одного прокатчика не распространяются на других.

**TRV-U19 — Отмена, возврат, обмен.** Возврат уменьшает расходы в периоде фактического получения и сохраняет связь/категорию покупки, а не переносится к дате исходного билета/поездки. Gross/net доступны раздельно. Обмен с доплатой/возвратом, удержанный сбор, отменённая поездка и неиспользованный билет не позволяют обнулить реальный расход или создать отсутствующий refund.

**TRV-U20 — Сертификаты, мили и ваучеры.** Номинал/баллы/мили/кешбэк в личном кабинете и цена предложения не денежная операция. Реальная покупка сертификата/возврат в ваучер/доплата/списание баллов различаются по существующей модели и доказанным facts/links. Не считать повторно оплаченный сертификат и полную цену погашенного заказа, не придумывать стоимость мили или автоматически новый доход.

**TRV-U21 — Компенсация и совместная поездка.** Подтверждённая компенсация конкретного расхода может уменьшать net expense по PDF, не автоматически доход. Перевод другу/гида/хозяина без надёжного контекста первоначально unresolved; не создавать связь по одинаковой сумме/названию. Полная оплата за группу не автоматически личная доля; доли/возмещение по существующим операциям и явному решению, без семейных аккаунтов.

**TRV-U22 — Командировка.** Рабочая цель/личное правило/возмещение имеют приоритет в разрешённом scope. Сам билет в будний день/получатель-компания/корпоративная ссылка сайта не доказывают командировку. Аванс работодателя, суточные, зарплата, собственный перевод и refund не один income-kind; учёт по исходным фактам/links, не бухгалтерская система новых ролей.

**TRV-U23 — Валюта: строго RUB v1.** Общая аналитика v1 только RUB (PDF 3.6/3.8). Для иностранной покупки с рублёвого счёта — фактически списанная надёжная RUB-сумма; исходная валюта/сумма отдельно сохраняются по data model. Если есть только неподдерживаемый валютный statement без надёжного RUB — сообщить об ограничении, не складывать валюты/не подбирать курс сайта/даты/модели. FX портфеля не реализуется.

**TRV-U24 — Даты и пользовательская зона.** Booking/payment/posted, вылет/прилёт, заселение/выезд и дата refund различимы. Аналитика следует source/действующему контракту дат и часовому поясу пользователя, не всем Москва/зона отеля/получателя. Международный перелёт через полночь не переносит день оплаты. Дата сайта/тарифа не назначается операции.

**TRV-U25 — Источники и история.** SRC/IDX подтверждают только построчно описанный профиль, не все маршруты/филиалы/способы оплаты/банковские aliases. REF сохраняет прежние ограничения. HIST Ангара/i8fly не подтверждает текущие регулярные рейсы/юридическое правопреемство по редиректу. PEND прежних пакетов не закрываются этим документом. Историческая доказанная операция сохраняется даже при недоступном сегодня сайте.

**TRV-U26 — Международная доступность.** Русский язык/RUB/российский домен/написание авиакомпании не обещают приём карт, доступный маршрут/границу/визу/страховое покрытие. Технически подтверждённый международный профиль применим к историческим операциям; каталог не даёт актуальную туристскую рекомендацию или юридическую гарантию. Цены/скидки/беззалоговость/кадры с сайта в правила не копируются.

**TRV-U27 — Review по реальной причине.** Ясная профильная авиапокупка/гостиница/тур/перевозка — обычная категория без пометки за отсутствие itemized чека. Реальная неопределённость допускает обоснованную предварительную существующую категорию с видимым Стоит проверить и понятной причиной. Нет даже направления — не выдумывать. Неизвестный лист при ясном подходящем родителе сам по себе не причина Review.

**TRV-U28 — Раздельные facets и уверенность.** Merchant/категория/kind/role/link/dedupe confidence и Review reasons независимы. Подтверждение категории не снимает возможный дубль/неясный залог/несвязанный refund. Высокий model confidence не user_verified; средняя уверенность по прежней политике остаётся Review. Точность категории не доказывает качество модели/схемы целиком.

**TRV-U29 — Личная структура.** Пути starter — ориентир, применять существующие подходящие user IDs/переименования. Скрытые/удалённые категории не восстанавливать/не создавать молча; при отсутствии направления предложить выбор, не fallback в Прочие расходы. TRV новых категорий не вводит, включая отдельные круизы/прокат/страховки. Ранее одобренный MP-узел техники остаётся отдельным будущим решением.

**TRV-U30 — Сопоставление имён.** Явные формы раздела 2 — кандидаты, не наблюдённые bank descriptors. Внутри закрытой строки NFKC/casefold/ё-е/технические пробелы; значимые цифры/части/границы токенов сохраняются. Падежи/транслитерации/разделители только перечисленные, не общий stem/fuzzy/раскладка/склейка. Домен проверять как целый допустимый host/path, не подстроку evil-example; сходный домен не первоисточник.

**TRV-U31 — Приватность и display.** Кириллический alias не приказывает транслитерировать display name, естественное написание/согласованное сокращение сохраняется. Пользователь видит отдельное банковское описание по принятой модели. ФИО/обычные цифры/слово перевод не скрывать безусловно; карты/счета/договоры/телефоны/email/паспорт, обозначенные auth/операция/документ/терминал/ИНН/БИК и URLs защищены по согласованным правилам. Билеты/PNR/паспорт/QR/контакты/геотрек не отправлять AI/в Git; потребность классификации не открывает доступ к личному кабинету.

**TRV-U32 — Распределение суммы.** Подходящий обычный расход пользователь может разделить между своими категориями. Положительный UI-ввод, signed integer minor storage, одна валюта, точная сумма effective, максимум 50 частей, без нуля/остатка/превышения/float/overflow. Части заменяют parent в аналитике, не складываются с ним. Сложные debt/neutral/залог по своему контракту, не упрощённое разбиение. Source/vendor/страна/платёжный получатель сохраняются.

**TRV-U33 — Lifecycle и связи.** Повторный импорт/обновление глобального alias не теряют ручные правки/parts/links и не меняют dedupe-signature. Новая самостоятельная бронь не наследует произвольные доли старой. Частичный refund зависимых частей требует явных links/preview/конфликтов/Undo; не угадывать пропорции. Объединение/связь нескольких source-движений не удаляет их реальность.

**TRV-U34 — Единая аналитика.** Карточка, список, поиск/фильтры, обзор/график/бюджет и Analyzer используют одну effective модель: parts вместо parent, единые gross/net/refund/date/RUB-only. Явные текстовые даты/категории/условия Analyzer выше выбранного UI-контекста. Категория Путешествия не создаёт автоматически trip-group, геолокацию или новый бюджет/операции.

**TRV-U35 — Доступ и Registry.** Ownership/status/entitlement/RLS/deletion до разрешённого preview и повторно commit; client IDs не authority. AI только закрытый versioned Registry, без SQL/password/email/session/admin/HMAC/сырых выписок. Cache/schema/policy/catalog version согласованы. Необходимая несуществующая UI-функция — BLOCKED, не PASS по похожей ручке.

### Параметризация и протокол

1. **TRV-P01 — Покрытие форм:** Все 89 профилей/формы × достаточный контекст × недостаточный × ближайший конфликт C. HIST отдельный BLOCKED для новой текущей активации; не превращать кандидаты в наблюдённые aliases.
2. **TRV-P02 — Услуги и роли:** Перелёт/багаж/жд/пригород/автобус/круиз/прогулка/тур/отель/длительная аренда/ресторан/прокат/трансфер/доступ/холд/депозит/refund/компенсация/аванс/выплата объекту. Для неприменимого facet не изобретать точный ID.
3. **TRV-P03 — Продавец и источники:** SRC/IDX/REF/HIST, неполный/старый источник, agent/operator/перевозчик/объект/бренд товара/эквайер, исторический период/филиал. Прямой и сторонний Aviasales, .ru/.com Странника, разные объекты гостиничной группы.
4. **TRV-P04 — Категории и уверенность:** Starter/личные деревья/переименования/скрытые/удалённые/отсутствующий лист; ручное/конкретное/широкое/global/AI/bank. Ясное без Review, обоснованное предварительное, нет даже направления; разные причины confidence/review.
5. **TRV-P05 — Деньги v1:** RUB-only, фактически списанный RUB/оригинальная валюта/нет надёжного RUB, никаких FX/float; копейки/комиссии/удержание/аванс/остаток. Предложение/бронь/баллы не новые деньги.
6. **TRV-P06 — Parts:** 1/2/несколько/50/51, положительный UI/signed minor, точное равенство effective, ноль/остаток/перебор/overflow/иная валюта, parts вместо parent, debt/neutral/залог по своему контракту, links/preview/Undo.
7. **TRV-P07 — Lifecycle:** Первый/повторный импорт/ручная правка/новая бронь/исторический бренд/отмена/обмен/депозит/частичный refund/компенсация/сертификат/группа. Фактический parent после провала, не golden replacement; source/dedupe/links сохраняются.
8. **TRV-P08 — Даты:** Booking/payment/posted/даты поездки/заселения/refund различимы; пользователь восточнее/западнее UTC/граница месяца/международный перелёт. Не всем Москва и не на дату вылета, refund по фактическому периоду.
9. **TRV-P09 — Приватность:** Только синтетика, никакие реальные билеты/выписки/фото документов/PNR/QR/контакты/геотреки/секреты. Раздельные raw/безопасное описание/display/AI-проекция; не расширять маскирование обратно на все ФИО/цифры.
10. **TRV-P10 — Безопасные пути:** Import/preview/commit/Undo/model/cache/Registry, ownership/status/entitlement/RLS/deletion до чтения и повторно commit, разрешённый UI. Недоступный путь — BLOCKED с причиной, не mock-PASS.
11. **TRV-P11 — Поверхности:** Карточка/операции/поиск/merchant-category фильтры/обзор/графики/бюджеты/Analyzer: единая effective/RUB/gross/net/refund/date математика, parts вместо parent. Явное текстовое условие выше UI-контекста, нет нового trip-group от категории.
12. **TRV-P12 — Результат и расход:** Версии каталога/schema/Registry/policy/cache, synthetic input, original raw/usage/validator/app decision, expected/actual/Review reason/фактический parent/source/parts/links/totals. PASS/FAIL/BLOCKED/NOT_RUN по слоям, model meaning отдельно от защитного отказа; replay и новый POST/usage/старый общий лимит раздельны, не продлевать admission/не повторять неопределённый POST автоматически.

Позднее сохранять **PASS / FAIL / BLOCKED / NOT_RUN** с причиной отдельно для источника/модели/schema/evidence/compiler/финансовой модели/UI/access/неверного oracle. Приложение может корректно отвергнуть неверную модельную категорию: PASS защиты не превращает смысл ответа модели в PASS. Original raw не исправляется задним числом. Ясный профиль без itemized чека — правильное обычное назначение, пустая категория/Review не универсальная стратегия безопасности. Никакие реальные документы/геотреки/контакты/брони для этих проверок не нужны.

Структурная проверка сейчас: уникальность/непрерывность 89 TRV / 36 U / 44 C / 88 T / 12 P, 714 явных форм, статусы, наличие по каждому профилю категории/ограничения, точное сохранение R11 forms, локальные ссылки и формат. Это **проверка документа**, ни один TRV-T не выполнен; новые POST — 0.

## Итоговое согласование и очередь

Четыре пункта TRV представлены одним подробным пакетом. **Итоговое согласование владельца нового TRV ещё впереди.** Новые категории, правила получателей/поездки/операции/продуктовые функции не создаются автоматически. Старые R/MP/ENT/EDU/DIG/FS/FASH/HOME и source/user/effective/parts/links/dedupe/RUB/access/privacy сохранены. Согласование проекта не закрывает HIST/старые PEND/конкретного неизвестного оператора/платёжный alias.

Следующий набор — **Питомцы**, затем **Подарки и благотворительность**, после них сверка оставшихся направлений. Реализация и общий прогон остаются после всего согласованного справочника.
