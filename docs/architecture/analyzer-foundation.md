# Основа серверного Анализатора

11 октября 2026. Stacked feature branch поверх полного Обзора; baseline 1.3 и полный PDF/Word неизменны. Основание: PDF 26–29, 35.4–35.6, 51–52; A-02/A-06 и B-09. Этот блок закрывает foundations из implementation plan, а не весь AI из PDF.

В авторизованном приложении доступны сохранённые отдельные диалоги, названия по первому поддержанному финансовому вопросу, поиск по названиям и сохранённым вопросам, закрепление, переименование и подтверждаемое удаление. История содержит structured snapshots, semantic query, action reference и dependency IDs. Сервер возвращает сообщения только выбранного диалога: максимум 100 диалогов и 100 вопросов в одном. Transaction database в чат не копируется. Удаление диалога не отменяет финансовые действия и не возвращает потраченную AI quota.

Точный конечный интерпретатор поддерживает расходы, доходы, категории, внимание, три крупные операции и сравнение расходов с предыдущим периодом. Поддержаны явный месяц/год, диапазон ISO-дат, «А по категориям?» и «А за [месяц год]?». Даты вопроса заменяют глобальные даты, остальные условия сохраняются. Неподдержанный период не игнорируется. Каждый follow-up заново читает текущую БД и рассчитывает тот же terminal graph через finance-core; старый ответ остаётся снимком. Все денежные значения — integer minor strings/BigInt. Ответ содержит период, filters, количество операций и счетов, сохранённый результат и «Как рассчитано»; в чате ограниченный preview, точный переход в Операции и сохранение отдельного представления на Обзоре.

## Контроль действий и данных

Registry `analyzer/1` содержит только `query_finances` и `set_inclusion`, strict parsers, owner/active-entitlement scope и confirmation policy. Unrelated, ambiguous, неподдержанные финансовые вопросы и injection-текст не читают transaction graph и не вызывают адаптер. Это конечная безопасная граница, а не обещание полноценной semantic AI classification четырёх классов. Произвольные SQL, другие users, security/admin/entitlement/HMAC commands отсутствуют. Внешний адаптер не может менять показатель, условия или scope запроса; суммы всегда рассчитывает наше ядро.

`set_inclusion` получает ID сохранённого ответа, а backend устанавливает фиксированные operation IDs по его условиям и метрике. Максимум 1000 операций; before/after и точный scope показываются общим предпросмотром. Только явное подтверждение вызывает общий commit. Permissions, status, entitlement, generation/revision/dependencies проверяются сервером повторно. Результат связан с `action_id`, виден в чате и History, поддерживает проверенный Undo. Подготовленный предпросмотр можно повторно открыть; действия старого финансового снимка блокируются при изменении базы. Неатомарные массовые задачи этим блоком не вводятся.

Browser sanitization применяется к вопросу, названию и поиску до отправки; backend повторно проверяет текст. Никаких raw statements/identifiers, transcripts, SQL, credentials или полного набора операций в provider contract. Финансовые запросы/диалоги не идут в URL, local/session Storage, telemetry или server logs. Удаление операции или отменённого source удаляет зависимый диалог целиком, включая текст и follow-up context; учитываются связи за пределами видимого периода. Не связанные диалоги сохраняются. Полный сброс с ротацией ключа очищает также чаты без transaction dependencies. Предпросмотр deletion/reset/cancellation показывает количество затронутых чатов. Категории/контрагенты, удалённые через reversible structural editor, остаются частью исторического снимка; старый узкий scope требует новой настройки, если reference больше недоступен. Полное rebind всех structural semantic references остаётся следующим расширением.

## Квота и провайдер

Обычные точные расчёты, basic Review и короткие unrelated/clarification replies не расходуют quota. Policy берётся из канонического `commerce.access_cycle`; неизвестная quota отображается как неназначенная. Monthly grid рассчитывается от исходного anchor/time в Europe/Moscow, с независимым month-end clamp каждой границы. Раннее продление и изменение policy сохраняют текущий usage. Есть remaining/reset date и пороги 80/95/100. Исчерпание блокирует только задачи адаптера; старые диалоги и детерминированные инструменты при активном entitlement доступны.

Учёт одной успешной задачи синтетического адаптера — одна test unit. Ledger хранит request ID, period, units, input/output tokens, provider/model/version; точный retry не вызывает адаптер снова и не списывает вторично. Ошибочная schema/scope не сохраняет ответ и не списывает лимит. Параллельные последние запросы сериализуются общей access/workspace lock. Deletion/reset не обнуляют usage. `control_api` может читать только usage metadata; financial chat tables закрыты для control/mail. Денежная себестоимость и тарифная единица production AI не выдумываются: их определит принятый provider/price policy.

По умолчанию внешнего AI нет. Единственное подключение — явный `test-fixture` adapter в `environment:test`, без сети; frontend честно отличает точный расчёт от теста модели. Development не принимает этот адаптер. Реальная модель Yandex, retention/config/privacy acceptance, error/retry/reservations вокруг внешних сетевых стадий, расход web/documents и admin quota add/override UI ещё требуют отдельного блока. API keys не добавлялись, услуги не покупались.

## Миграция и проверки

Operator migration `0022_analyzer_foundation.sql` после 0021 добавляет FORCE RLS, tenant-bound chat/message/dependency keys, immutable identity, privacy cascade triggers и независимый metadata ledger. Команда Development operator: `migrate-analyzer`. После первого сохранённого диалога старый runtime нельзя считать безопасным rollback: он не знает новые deletion/reset зависимости. Нужен совместимый reader/cascade или forward-fix; таблицы и ledger не удаляются ради rollback.

Проверки: finite Registry/privacy/date/context unit tests; PostgreSQL gate canary, owned scope, persistence, concurrency, idempotency, quota, deletion/reset/control separation; real authenticated HTTP/Chromium desktop/mobile chats/actions/reload/Undo; UI sanitation, exact retry, delayed access loss, explicit deletion и Overview save. В CI отдельное analyzer-checks дополняет весь существующий набор. Фактические результаты окончательного head и число тестов фиксируются в PR после завершения; synthetic screenshots проверяются отдельно.

Полный natural-language Analyzer, все группы Registry, external web/freshness, financial documents/OCR/page consent, deterministic loan calculators, production provider/retention, admin usage interface, реальное Staging acceptance и Production не объявлены готовыми.
