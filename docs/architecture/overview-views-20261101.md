# Представления обзора: согласованный интерфейс 01.11.2026

Владелец согласовал управление представлениями непосредственно в обзоре. Этот документ уточняет разделы 21.6–21.8 `docs/product/master_spec_v1.pdf`: общие фильтры теперь независимы от представления, отдельного экрана настроек представления нет.

## Поведение

- В заголовке находится текущее имя и меню представлений: выбранное отмечено галочкой, начальное — пометкой «По умолчанию». Меню каждой записи: переименование, создание копии, выбор начального, удаление. Внизу — создание представления.
- Новое именованное представление пустое. Копия содержит виджеты, их локальные условия и оба расположения. Копирование текущего включает его черновик; источник остаётся сохранённым без изменений. Имена не повторяются после приведения регистра, пробелов и Unicode.
- Изменения виджетов/расположения образуют черновик. «Сохранить» обновляет текущее представление; стрелка открывает «Сохранить как новое». «Сбросить» возвращает последнюю сохранённую версию. Переименование или назначение начального представления отдельно не сохраняет черновик виджетов.
- Переход с черновиком предлагает сохранить, не сохранять или остаться. При открытом редакторе сначала решается судьба правок конкретного виджета.
- Общие даты, категории, банки и счета сохраняются при переключении представлений и не создают черновик. В существующих записях устаревшие сохранённые общие фильтры не применяются. При явной записи передаются пустой общий фильтр и период `all`; локальные условия виджетов сохраняются. Чтение не переписывает старые записи. Общие фильтры не становятся постоянными при перезагрузке страницы.
- Компьютер и телефон используют общие виджеты и настройки, независимые расположения и видимость. Изменение размеров доступно только на компьютере. Видимость, копия и удаление виджета находятся в его редакторе; скрытые виджеты доступны из обзора.
- Удаление требует подтверждения. Удаляется только представление; операции и банковские факты сохраняются. После удаления последнего открывается встроенный стандартный обзор. Последнее сохранение/удаление можно отменить уведомлением.

## Сохранность и границы

Существующие закрытые команды `save_overview_view`, `delete_overview_view` и `undo`, серверная авторизация, проверка generation/revision, preview/commit и идемпотентность остаются прежними. Устаревший диалог не перезаписывает новое состояние; повтор после потерянной квитанции использует тот же actionId. Новые таблицы и миграции не требуются. Тарифы, допуск ИИ, незавершённые запросы, резервы и расходы этим изменением не меняются.

## Проверки

Добавлены модульные проверки нормализации общих фильтров, сохранения локальных условий/расположений и имён копий. Браузерные сценарии проверяют меню, создание пустого представления, копирование черновика, дубли имён без POST, все три варианта перехода, независимость переименования, удаление/Undo, конкурентное изменение и повтор потерянного commit на компьютере и телефоне. Проверка реального API/PostgreSQL с 15 003 операциями обновлена под новый интерфейс, включая независимые расположения, начальное представление и отсутствие записи финансовых данных.

Результаты кандидата фиксируются в GitHub Actions для конкретного SHA; наличие кода не означает его установку на Staging.
