## 1. Названия, источники и пределы подтверждения

Это практическая подборка для РФ, не исчерпывающий реестр всех банков, МФО, НПФ, взыскателей/налогов/страховщиков. Не рекомендация организации, не юридическая или налоговая консультация и не проверка доступности каждого продукта. Никаких тарифов/ставок/скидок/сроков взыскания из рекламных страниц в правила не переносится.

Просмотр/попытки первичных источников: 27.10.2026; дата реестра/документа может отличаться. **REG** подтверждает реестровое имя/тип организации в описанном объёме; **SRC** — прочитанный первичный профиль; **IDX** — первичный текст через индекс, не прямое чтение всей страницы; **HIST** — историческую identity с ограничением текущей применимости; **REF** — существующий профиль без повторного разрешения aliases; **PEND** — новая глобальная identity BLOCKED до достаточного первичного подтверждения. Это не статусы точности модели. Банковские homepages, которые не удалось прочитать, не помечаются SRC: используется реестр ЦБ. Ни один источник не удостоверяет все банковские descriptor-формы.

Реестры ЦБ: [список организаций](https://www.cbr.ru/banking_sector/credit/FullCoList), [заявленные сайты](https://www.cbr.ru/banking_sector/credit/cowebsites/), [участники финансового рынка](https://www.cbr.ru/finorg/). Указание реестра не делает страну/группу/похожее название алиасом. Полные реквизиты источников не копируются в этот каталог и модель.

## 2. Явные написания и нормализация

Формы ниже — **наши кандидаты**, не извлечённые из реальных выписок. NFKC/регистр/ё-е и повторные пробелы нормализуются для поиска без изменения bank/source. Дефисы/кавычки/юридические обрамления проверяются отдельно, не глобально склеиваются. Домен в источнике не означает разрешение распознавать любой платёж по URL: URL скрывается в AI projection; локально доказанный безопасный merchant-признак остаётся отдельным полем.

Словоформы конечны: Сбербанка/Сбербанке допустимы как кандидаты, но не свободный стемминг всех слов. Короткие МКБ/OTP/Мир/Cloud/Точка/Россия и смешанные буквы не безусловные aliases. Источник-банк, банк получателя, платёжная инфраструктура и merchant хранятся раздельно. Общий словарь «слово → деятельность» и окончательные правила упрощения display-name остаются отдельными этапами. TimeWeb не превращать в «Таймвэб» автоматически.

### Смысловые признаки финансового события

## 3. Категории, роли и правила

Переиспользуются существующие ветви: **Банковские услуги → Обслуживание / Комиссии / Уведомления / Прочие банковские услуги; Кредиты и долги → Платежи по кредитам / Проценты / Страхование по кредиту / Прочие расходы по кредитам; Налоги и обязательные платежи → Налоги / Штрафы / Госпошлины.** Для жилья, страхования, госвыплат, процентов, кэшбэка и пользовательских категорий действует соответствующее назначение. Нет нужной категории — предложить существующую подходящую/выбор, не создавать новую глобальную автоматически. Категория не превращает neutral в expense.

### Требования к параметризации

1. **FIN-P01 —** Имена: каждый FIN-профиль/форма, юридическая обёртка/пробел/дефис/регистр/ё-е/NFKC; отрицательные чужие токены/границы/омонимы; PEND/HIST/REF не повышаются.
2. **FIN-P02 —** Контекст: source bank/merchant/counterparty/account/channel отдельно; краткое имя без банковского поля, отрицание, 0 fee, нет движения, исторический период.
3. **FIN-P03 —** Категории: starter/личное дерево, nested/hidden/deleted, role совместимость, близкие названия/транслит только явные, категории пользователя не создавать по названию банка.
4. **FIN-P04 —** Приоритет: manual/verified, specific/broad personal, global/AI/bank, snapshot/version/cache, historical impact preview, no retroactive overwrite.
5. **FIN-P05 —** Кредитные режимы: credit card/обычный loan, global/account overrides, известные/неизвестные components, incomplete banner vs operation Review, cashflow/economic и исключение repayment отдельно.
6. **FIN-P06 —** Знаки/состав: issued/paid/received, principal/interest/fee/insurance, cashback/refund/reimbursement, own/private/debt transfer; neutral не общий fallback для непонятного.
7. **FIN-P07 —** Деньги: integer minor, RUB-only, actual RUB/original foreign, 0/отрицательное/округление/overflow, нет вымышленных FX/процентов/налоговых ставок.
8. **FIN-P08 —** Parts/links: 1/2/50/51, сумма/валюта, allocation capacity/cycles/status/candidate/confirmed/rejected/user conflict, parts вместо parent, complicated graph не simple purchase split.
9. **FIN-P09 —** Жизненный цикл: import/reimport/reset/cancellation/manual edits/rule update/delete/Undo; исходные account/source/HMAC/dedupe/merchant/links сохранены.
10. **FIN-P10 —** Даты: source-local operation/posted отдельно, profile today/relative periods/UI timestamp, UTC ± зоны/границы месяца/переезд; исторический refund не backdate.
11. **FIN-P11 —** Приватность: только синтетика, safe projection без реквизитов/URL, raw/source/display/AI поля отдельно; разрешённые ФИО и обычные цифры не blanket redaction, HMAC/access не модели.
12. **FIN-P12 —** Права: ownership/user status/entitlement/deletion/RLS до preview и повторно commit; Registry version/limits, кэш не authority, нет SQL/admin/session/password/HMAC.
13. **FIN-P13 —** Поверхности: import/Review/card/Operations/search/filters/Overview/Budgets/Analyzer/export, parent+components не двойной расчёт, account override неизменный во всех местах.
14. **FIN-P14 —** Протокол: versioned fixtures/oracle/schema/raw/model/schema guard/compiler/core/UI/access outcomes; PASS/FAIL/BLOCKED/NOT_RUN с причиной, costs/archive reuse/new POST отдельно, unknown POST не повторять автоматически.
