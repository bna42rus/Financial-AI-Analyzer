# Установка при открытом резерве Staging

После потерянного ответа runtime-категоризации в журнале может остаться unknown request и удержанный резерв. Это не подтверждённая сумма списания. Удалять запись, освобождать резерв или придумывать token usage нельзя.

Для ещё действующего допуска разрешена только смена привязки исходников через существующую проверку двух сохранённых синтетических PASS: текущие входы, смысл ответов и оплаченные квитанции проверяются заново. Новых POST нет. Политика, период, срок, ключ, пользователи, лимиты и прежний учёт не меняются; открытые записи и деньги остаются на месте. Это позволяет установить исправления интерфейса. Runtime-ограничители unknown receipt остаются включены, поэтому такое обновление не объявляется восстановлением модельных запросов.

Продление истёкшего допуска с открытым резервом по-прежнему запрещено. Provider contract freeze, подменённые архивы и отсутствие оплаченной квитанции отклоняются. Сверка неизвестного расхода требует отдельного подтверждения фактического usage провайдера.

Проверки: неизменность активного допуска и переданных итогов при rebind с резервом, запрет rollover после истечения и при blocked provider, отказ в неверных итогах, прежние проверки paid evidence и установщика.
