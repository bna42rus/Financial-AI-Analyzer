# Техработы: установка и проверка

- Миграция 0056 создаёт одну общую запись состояния и отдельный аудит; PostgreSQL время является источником истины. Finance имеет только SELECT, Control — SELECT/UPDATE и добавление аудита. Административный HTTP обработчик всегда проверяет requireAdmin/TOTP. Установщик применяет миграцию после резервной копии и до переключения API.
- Публичный GET /public/maintenance не раскрывает данные администратора. Во время активного окна обычные Finance маршруты отвечают 503 + Retry-After, отдельный PSP webhook не блокируется. Обычный /health остаётся проверкой API, не признаком окончания техработ.
- Уже начатые запросы и стадия импорта завершаются атомарно. Следующая стадия импорта ждёт. Фоновые платёжные процессы продолжаются. Никаких изменений платёжных календарей/квот/пользовательских сессий нет.
- В админке один раздел «Техработы». Ручное окончание не является проверкой бизнес-функций: администратор предварительно убеждается в готовности сайта и API, затем подтверждает открытие. Одного истечения планового end недостаточно.
- Аварийная команда, не зависящая от админки/API: sudo python3 scripts/maintenance-control.py start --until ISO_WITH_OFFSET. Только Staging localhost:5411; status/finish/cancel/extend также доступны. Команды не деплоят код и не меняют AI.
- Статический frontend остаётся доступным при остановленном Finance API; показывает сохранённое публичное расписание либо честное сообщение о временной недоступности. Поддержка работает локальным окном с адресом/копированием. Юридические документы остаются доступны.

Локально проверены типы трёх приложений, сборки web/admin, шесть серверных сценариев и браузерные: расписание, старт/завершение из админки, автоматическая смена экрана, сохранение черновика, скрытие прежнего диалога, поддержка, превышение срока, возврат в приложение, недоступность API. Мобильный и компьютерный вид просмотрены. Реальный PostgreSQL для локального прогона миграции отсутствует. В существующем полном тесте установщика четыре случая требуют root-owned fixture и останавливаются на PRIVATE_CONFIGURATION_REQUIRED в текущем окружении; остальные 15 проходят.

Проверка владельцем на Staging: назначить окно менее чем через сутки; проверить плашку; начать сейчас; проверить API 503 и поддержку; изменить сообщение/окончание; завершить; вернуться без нового входа. Не включать техрежим Production этой командой.

Откат: стандартный сохранённый установщиком rollback восстанавливает прежний релиз. Новые таблицы с публичным расписанием/аудитом недеструктивны и остаются в БД. Версии до этой функции не обеспечивают maintenance gate: при возврате к ним администратор должен контролировать момент открытия сайта отдельно. Предпочтителен исправляющий релиз, пока текущий техрежим остаётся включённым.
