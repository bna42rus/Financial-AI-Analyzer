### Единые правила GFT

**GFT-U01 — Приоритет и предел этапа.** Ручное решение операции → конкретное личное правило → широкое личное правило → global → AI → допустимый bank facet. Название магазина/фонда не меняет source/merchant/сумму/дату/kind/role/links/parts. Более конкретный предмет/цель/решение выше типичного профиля. Массовое применение к истории по действующему impact preview, не молча.

**GFT-U02 — Подарок — экономическая цель.** Установленный подарок другому/подарочная услуга/упаковка подарка → Подарки. Обычная книга/украшение/техника/детский товар себе сохраняют ENT/FASH/MP/EDU. Дорогая покупка, день рождения/праздник в календаре, пол/возраст/семейный статус, слово подарок в рекламе не доказывают дарение. Не нужно узнавать имя/отношения с получателем для ясной категории.

**GFT-U03 — Обычный букет.** Для установленного обычного букета/подарочной композиции узкопрофильной цветочной предлагается типовой Подарки без Review только за отсутствие получателя/повода/чека. Это проект финансового default, не доказательство реального дарения/романтических отношений. Явная покупка для себя/дома, горшечное растение, семена/расходники/работа выше этого default.

**GFT-U04 — Широкие цветочные и подарочные площадки.** Flowwow/7ЦВЕТОВ/LeFutur/PichShop могут иметь разный товар и B2B. Не все покупки подарки от маркетинговой вывески. Известный подарочный предмет/сервис → Подарки, личное растение/товар домой/гаджет/рабочая закупка → своё направление. Если реально неоднозначно, допустимо обоснованное предварительное назначение с причиной, не выдуманный получатель/состав.

**GFT-U05 — Сертификат не обязательно подарок.** Giftery/Digift/Дарить Легко/PS Box и другие обслуживают разные цели. Подтверждённый подарок другому → Подарки; собственное использование с известной услугой/товаром по предмету/личному решению. Нельзя автоматически ставить Подарки по слову сертификат или назначать иной узел по одному имени эмитента. При реальной важной неоднозначности уточняется цель, не личность получателя.

**GFT-U06 — Доставка кода не цель покупки.** В первичной справке Дарить Легко Себе означает в том числе получить код для личного вручения. Email/телефон доставки/кнопка Себе/Другу/пересылка не надёжная финансовая цель всех сервисов. Не читать почту/контакты/чужой кабинет ради классификации, не передавать код/QR/номер сертификата AI.

**GFT-U07 — Цена, номинал и погашение.** В аналитику входит фактическая надёжная банковская RUB-сумма оплаты, не номинал/баланс/цена товара на сайте. Погашение ранее оплаченного сертификата без новой денежной операции не второй полный расход; реальная доплата учитывается только своей суммой. Не создавать виртуальный сертификатный счёт/кошелёк/доход/банковскую операцию, не внедрять новый prepaid-ledger.

**GFT-U08 — Полученный сертификат и входящий подарок.** Бесплатное получение сертификата/баллов/скидки без денежной операции само по себе не банковский income и не повторный расход по номиналу. Реальный денежный подарок входящий → подходящая существующая Подарки и помощь → Денежные подарки при установленном смысле/role; не расходная категория Подарки. Возмещение/refund/долг/заём/собственный перевод не определяются словом подарок.

**GFT-U09 — Впечатление и услуга.** Подарок-впечатление другому → Подарки. Собственный SPA/ресторан/курс/поход/билет по доказанному предмету BEA/еда/EDU/TRV/ENT. Покупка сертификата, выбор услуги, бронирование, активация и посещение не пять самостоятельных списаний. Не выдумывать доли пакета/не создавать сумму по прайсу.

**GFT-U10 — Корпоративные подарки.** Рабочая закупка/вознаграждение сотруднику/корпоративная программа/комиссия/доступ/выплата поставщику по фактической роли/личному правилу. Сам B2B-раздел сайта или будний день не доказательство рабочей цели пользователя. Не создавать бухгалтерию/налоговые выводы/рассылку подарков из категории.

**GFT-U11 — Обычное пожертвование.** Обычное установленное исходящее денежное пожертвование в подтверждённый благотворительный фонд/проект → Благотворительность без Review за отсутствие описания каждого благополучателя. Не требовать ФИО/диагноза/документов получателя помощи. Каталог подтверждает только профиль/категорию, не сертификат надёжности/законности/налоговой льготы каждого платежа или рекомендацию перечислить деньги.

**GFT-U12 — Фонд не все его движения.** Покупка товара/мерча/билета/курса, оказанная платная услуга, зарплата/грант/помощь благополучателю/компенсация/refund и пожертвование различимы. Один source merchant фонда не делает все входящие income или все исходящие charity. Если благотворительная цель покупки явно установлена пользователем, она имеет приоритет; товар с целью себе не превращать в пожертвование автоматически.

**GFT-U13 — Посредник, платформа и фонд назначения.** Благо/VK Добро/Tooba/СберВместе/Добро.рф могут быть каналом/платформой, конечный фонд/оператор/эквайер — отдельные facets по фактам. Не выбирать конечного получателя/подопечного из суммы/общего бренда, не подменять source merchant. Комиссия платформы и сумма помощи не две полные суммы из одной операции.

**GFT-U14 — Добровольчество и действия без денег.** Волонтёрские часы/регистрация/участие в акции/заявка на помощь/бесплатная услуга/публичный счётчик/чужой взнос не денежный expense пользователя. Реальное списание не обнуляется от наличия бесплатной услуги того же проекта; не создавать виртуальную сумму труда/рыночной цены помощи.

**GFT-U15 — Краудфандинг.** Planeta/Boomstarter могут собирать на благотворительный проект или давать продукт/билет/предзаказ/другое вознаграждение. Поддержка не автоматически пожертвование, инвестиционный актив или доход автора. По установленному предмету/цели/роли; при реально неясных условиях Review/уточнение, без домысливания юридической природы/гарантии возврата.

**GFT-U16 — Покупка с благотворительной целью.** Явная помощь приюту/фонду, адресная оплата товара/лечения в помощь другому, благотворительный лот или часть цены в пользу фонда требуют установленной цели/фактических сумм. Более конкретное личное решение выше retail/медицинского/пет default. Не делить взнос/товар/комиссию по догадке и не объявлять всю рекламную покупку пожертвованием.

**GFT-U17 — Округление и совпадающая помощь.** Помощь рядом/Petshop и другие акции могут включать отдельный фактический взнос, сумму в составе чека или вклад самой площадки. Не переводить весь чек Такси/покупки в Благотворительность. Parts только по известным точным суммам/пользовательскому решению; баллы/бонусы/удвоение компанией без денежной операции пользователя не его второй расход/доход.

**GFT-U18 — Регулярный взнос.** Регулярное подтверждённое пожертвование остаётся Благотворительность, не цифровая подписка от повторяемости. Возобновление платежей/привязка карты/отмена автоплатежа не выполняются классификатором и не следуют из личного правила. Будущие подписки не создают будущих банковских операций.

**GFT-U19 — Частный перевод.** ФИО, подпись подарок/на лечение/сбор/помощь в недостаточном контексте, имя человека/кличка или голая ссылка не доказывают фонд/подарок/пожертвование/роль. По PDF переводы первоначально unresolved без надёжного правила/контекста. Явное подтверждённое назначение/существующее личное правило применяются в scope; HMAC не открывать модели/не объявлять новым обучением получателя.

**GFT-U20 — Сбор от имени других.** Деньги на коллективный подарок/сбор с последующим перечислением не автоматически личный доход организатора и ещё один полный его расход. Реальные source/links/role/части и подтверждённый контекст по текущей финансовой модели; при неподдерживаемом сложном случае BLOCKED/уточнение, не новый тип чужих счетов/долгов/транзитного ledger. Личную долю не угадывать по числу участников.

**GFT-U21 — Возврат и компенсация.** Отмена заказа/сбора без реального возврата не обнуляет списание. Refund уменьшает net expense в периоде фактического поступления с исходной категорией/link, не переносится к покупке/дню дарения. ### Параметризация и фиксация результата

1. **GFT-P01 — Матрица форм:** Все 64 профиля/формы × достаточный контекст × недостаточный × ближайший конфликт C. PEND новая активация BLOCKED; REF не повышает старые источники; профиль не равен банковскому alias.
2. **GFT-P02 — Цель и предмет:** Подарок другому/покупка себе/букет/растение/B2B/сертификат/код для вручения/услуга/пожертвование/мерч/лот/предзаказ/взнос/волонтёрство/баллы/выплата. Не создавать личность/родство/диагноз/религию/продукт по одному имени.
3. **GFT-P03 — Роли и получатели:** Source merchant/магазин/эмитент/оператор платформы/фонд назначения/эквайер/частный сборщик/организатор/благополучатель различимы. Expense/income/neutral/unresolved/compensation/refund по действующему контракту, не от положительного знака/названия.
4. **GFT-P04 — Личные решения:** Starter расходный/доходный и несколько личных деревьев/переименования/скрытые/удалённые/отсутствующие IDs. Ручное→конкретное→широкое→global→AI→bank, scope/impact preview, ясное без Review/обоснованное предварительное/нет направления.
5. **GFT-P05 — Деньги:** RUB-only, actual/номинал/скидка/доплата/вознаграждение/округление/комиссия/вклад платформы/подаренный сертификат; integer minor/копейки. Нет FX/виртуального счёта/неденежного income/полного расхода повторно.
6. **GFT-P06 — Parts:** 1/2/несколько/50/51, positive UI/signed storage, точное равенство effective/валюте, 0/остаток/перебор/overflow, parts вместо parent. Сложные neutral/debt/чужой сбор по контракту, dependency/preview/conflict/Undo.
7. **GFT-P07 — Lifecycle:** Первый/повторный импорт/ручная правка/новая покупка/глобальное обновление/предоплата/погашение/отмена/частичный refund/компенсация/коллективный подарок. Фактический parent после провала, не golden подмена, source/dedupe/parts/links сохранены.
8. **GFT-P08 — Даты:** Source payment/posted/дарение/доставка/погашение/услуга/акция/refund различимы; пользователь восточнее/западнее UTC/граница суток/месяца. Не всем Москва/не к празднику, refund в фактическом периоде.
9. **GFT-P09 — Приватность:** Только синтетика: нет реальных выписок/данных благополучателей/диагнозов/контактов/кодов/номеров сертификатов/QR/секретов. Raw/safe description/display/AI projection раздельны, прежняя видимость ФИО/цифр не открывает реквизиты/URL.
10. **GFT-P10 — Доступ:** Import/preview/commit/Undo/model/cache/Registry, ownership/status/entitlement/RLS/deletion до чтения и повторно commit, server authority. Нет разрешённого UI-пути — BLOCKED с причиной, не mock PASS.
11. **GFT-P11 — Поверхности:** Операции/карточка/поиск/merchant-category фильтры/обзор/графики/бюджеты/Analyzer: одна effective/parts/net/gross/refund/date/RUB модель, явное условие выше UI. Не создание автоплатежа/нового счёта/профиля получателя из категории.
12. **GFT-P12 — Протокол:** Версии catalogue/schema/Registry/policy/cache, synthetic input, original raw/usage/validator/app decision, expected/actual/Review reason/реальный parent/source/parts/links/totals. PASS/FAIL/BLOCKED/NOT_RUN по слоям, model meaning отдельно от app guard; архив/новый POST/расход/старый общий лимит раздельны, admission не продлевать/не повторять неопределённый POST автоматически.

Позднее фиксировать **PASS / FAIL / BLOCKED / NOT_RUN** с причиной отдельно для источника/model/schema/evidence/compiler/финансовой модели/UI/access/неверного oracle. PASS защитного отказа не означает PASS смысла модели; original raw не переписывается. Правильный ясный исход без чека/личных подробностей — обычная категория, пустая категория/Review не универсальная стратегия безопасности. Реальные документы/диагнозы/контакты/коды для этих проверок не нужны.

Структурная проверка сейчас: непрерывность/уникальность 64 GFT / 36 U / 40 C / 80 T / 12 P, 596 явных форм, источник/категория/ограничение каждого профиля, точное сохранение 6 REF inventories, локальные ссылки/формат. Это проверка документа, **ни один GFT-T не выполнен**, новые POST — 0.
