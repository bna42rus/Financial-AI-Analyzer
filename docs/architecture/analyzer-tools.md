# Внутренние инструменты Анализатора

Продолжение foundation PR #38, baseline 1.3. Основание: полный PDF 27, 35.5–35.6, 51–52; согласованные A/B/E сохраняют приоритет. Документы, калькуляторы, квоты и внешняя модель — отдельные следующие блоки.

Registry `analyzer/2` добавляет `edit_operations` и `finance_action`. Первый меняет существующие поля операций, включая категорию, подкатегорию, kind/role, merchant, counterparty, comment, review, inclusion и одиночную correction. Второй допускает конечный список уже реализованных backend intents: счета, категории, контрагенты, правила, analytics, бюджеты, Обзор/представления Операций, links/components, дубли, история и отмена импорта. Каждый intent повторно разбирается строгим parser соответствующего модуля; SQL, security/admin/entitlement, произвольные таблицы и неизвестные команды недоступны. Новые команды требуют изменения версии Registry и реализации backend.

Транзакционные действия привязаны к результату сохранённого ответа и его метрике/фильтрам; UI pagination и topN не ограничивают выборку. Можно передать точное подмножество, максимум 1000 операций. Другие ID отклоняются. Links и пары дублей должны находиться в выбранном scope. Структурные изменения и настройки могут затронуть данные вне периода ответа; общий preview показывает их полный impact. Операции этого impact добавляются в privacy dependencies диалога. Последующее физическое удаление затронутой операции очищает и этот диалог, даже если её не было в первоначальном ответе.

Авторизация, ownership, status/entitlement и финансовые generation/revision проверяются до preview и при commit. Предпросмотр использует общий finance/action pipeline, History и Undo; новые SQL mutation handlers не вводятся. Повтор одного actionId/tool возвращает тот же подготовленный или завершённый результат. Другой payload либо чужое действие с тем же ID отклоняются. Подготовленный scope не пересчитывается при retry. Просроченный или устаревший preview требует нового вопроса/предпросмотра. В сохранённом диалоге доступен исходный tool и результат действия; его preview можно открыть после перезагрузки. Открытие сохранённого предпросмотра всегда показывает последствия до commit.

PDF 51: одна обычная обратимая правка, название счета/категории/контрагента, создание категории и explicit future rule не требуют дополнительного confirmation, после них доступен Undo. Массовые изменения, broad exclusions, account type/loan mode, категория с migration, merge/split, bulk restore и cancellation требуют общего impact preview и одного commit. Correction использует принятый correction flow с preview. Необратимая отмена импорта и операция deletion не обещают Undo. Reset и account/period/deep-counterparty destructive deletion маршрутизируются через существующие специальные экраны: Registry не обходит их reauthentication и подтверждения.

Поле вопроса появляется после загрузки диалогов. Обработчик фиксирует строку ввода до отложенного React updater, чтобы текст не терялся при восстановлении controlled textarea. Во время запроса повторная отправка заблокирована, но изменённый черновик следующего вопроса сохраняется. При финансовом preview поле скрыто до завершения общего действия. Браузерные проверки вводят первый вопрос через обычное поле, без программного вызова React handlers.

UI «Изменить данные» позволяет назначить категорию и другие поля операциям ответа, создать/переименовать категорию, переименовать счет/контрагента, изменить включение future rule и модель учета кредитов. Перед сетью строки очищаются, backend проверяет их повторно. Это интерфейс для проверки внутренних инструментов до подключения модели; свободный текст произвольного действия пока не интерпретируется. Полные формы сложных структурных действий остаются в соответствующих экранах. Инструменты documents/calculators/internet и новая семантика read/review требуют следующих модулей.

Миграция не нужна: metadata закрытого tool/confirmation хранится в существующем finance.action JSON, связь с диалогом и privacy cascade используют 0022. Для deployment сохраняются ограничения foundation: старый runtime не знает все chat dependencies; rollback требует совместимого reader/cascade либо forward-fix. Production и Staging acceptance этим PR не выполняются.

Проверки: строгий Registry/confirmation; PostgreSQL ownership, scope, retries, history/Undo, future-rule и destructive gates; реальные HTTP/Chromium desktop/mobile правки, восстановление preview после reload, commit и Undo; UI unit и E2E; весь существующий CI. Финальный статус конкретного head фиксируется в PR.

Локальная проверка окончательных изменений: 219 тестов ядра, 79 Web unit, 8 API unit, 30 PostgreSQL и 2 real HTTP/Chromium сценария, 24 Web E2E desktop/mobile — всего 362 без повторного учёта. Проверки исходных документов, типов и обе сборки прошли; desktop/mobile screenshots просмотрены. Локальный временный PostgreSQL — версия 16; полный CI на PostgreSQL 18 и owner Staging acceptance ещё не выполнены. Исчезающий ввод, сохранение нового черновика во время запроса, доступность полей редактора, потеря acknowledgement и попытка расширить answer scope через set_exclusion проверены отдельно.
