# NAME — упрощение отображаемых названий операций

Дата: **28.10.2026**. **Полный проект отдельного этапа NAME для просмотра владельцем; runtime/сайт не переключены.** Поручение «Ок давай» после ACT разрешает подготовить этот этап, а не выдумать историческое согласование новых примеров. Все четыре части представлены вместе: данные/приоритеты, алгоритм/написания, конкретные преобразования, проверки/адресные реализации.

**Главное решение:** короткое имя — отдельная **read-only проекция интерфейса**. Исходное очищенное описание, merchant identity/matching, личные правила, суммы/даты/счета, категории, части и связи не переписываются ради красивого title. У известных профилей сохраняются конкретный сервис и полезное пояснение способа получения. Неизвестные Кафе Москва/Магазин 24/ИП Иванов Иван 24 не обрезаются произвольно.

**Объём:** 48 правил NAME-R01–R48; 8 смысловых полей проекции; 12 типов сегментов; 36 конечных style bindings; 86 будущих семейств NAME-T001–T086 NOT_RUN; 6 адресных точек реализации NAME-I01–I06. Все 194 ACT-деятельности/4282 формы и предыдущий merchant-корпус сохранены. Новых paid POST **0**.

## 1. Какие данные и что видит пользователь

| Слой | Назначение | Влияние NAME |
|---|---|---|
| Банковский факт/очищенное описание | Исходные разрешённые сведения банка в действующих пределах/санитизации | Не меняются и доступны отдельно |
| Merchant/party identity и matching | Каталог/aliases/личные правила/HMAC/source bindings | Не заменяются красивым названием |
| Имя владельца/правила | Явный разрешённый private assignment и userVerified | Приоритет над автоматическим стилем |
| UI-проекция NAME | Короткое читаемое имя + реальные пояснения | Read-only вывод, не изменение финансового graph |
| Категория/роль/parts/links/Review | Независимые финансовые/аналитические facets | Не изменяются названием |

Имя не обязательно одна новая строковая колонка в БД. Проекция собирается из доступных существующих полей/проверенных сегментов; это не утверждённая миграция модели. Любые новые persisted assignments потребуют прежнего явного action/preview/commit.

### Поля представления

| Поле | Смысл | Право записи |
|---|---|---|
| title | Основной полный допустимый title: защищённое личное имя, торговое имя/конкретный сервис либо честный fallback. | NONE_READ_ONLY |
| eventLabel | Существующий фактический вид/статус события — например Возврат/Перевод. Это не новое финансовое событие, не merchant и не услуга. В одно-поле представлении идёт перед title; одинаковый title-смысл не дублируется. | NONE_READ_ONLY |
| serviceQualifier | Только известная услуга, различающая продукты группы; не вывод из guessed category. | NONE_READ_ONLY |
| fulfillmentQualifier | Доставка/самовывоз только по доказанному способу того же заказа. | NONE_READ_ONLY |

### Как выглядит одна операция

- **Пятёрочка** · **Доставка**; в одном текстовом поле — **Пятёрочка — доставка**. Слово продукты в исходной строке не обязательно.
- **Яндекс Go** · **Аренда пауэрбанка**, если услуга подтверждена; не придуманный «Бери заряд» и не безликий Яндекс.
- **Яндекс Go** без услуги остаётся Яндекс Go; категория Такси+Review не превращается в доказанное название поездки.
- **Ozon Fresh** сохраняет Fresh; **TimeWeb** сохраняет ранее выбранное владельцем имя, конкретный облачный/хостинговый продукт и получатель не сливаются.
- **Перевод — Иван Петров** — только из допустимого actual event/party-текста/собственной карточки; это не merchant и не доказательство HMAC-идентичности/родства/подтверждённой связи.
- **Продавец не определён** — лишь если допустимых сведений действительно нет; отдельно вид/статус операции и очищенное описание.

Порядок composite: фактический eventLabel при необходимости → title → известная отличающая услуга → способ получения → через агрегатора. Не повторять Доставка, если это уже полное имя Яндекс Доставка, и не потерять пояснения на поверхности, где отдельные badges не видны.

### Приоритет

1. Защищённое имя владельца/применимого правила в пределах privacy.
2. Адресный ранее согласованный override TimeWeb; будущие иные overrides — только явно зарегистрированные.
3. Доказанный профиль/конкретный сервис и конечный same-script style, если он принят и активирован для нужного периода.
4. Полезный допустимый merchant span в исходной письменности; неизвестный сохраняется целиком, без обрезки по стоп-словам.
5. Допустимый actual event/party/предмет очищенного описания; иначе честный fallback.

**Смена алфавита не автоматическая:** PYATEROCHKA может остаться PYATEROCHKA, Пятёрочка — Пятёрочка. Согласованный будущий адресный русский display override может выбрать русский public label, но одна русская подпись каталога/сайт не включает его глобально. Неописанные профили уже покрыты конечным SOURCE_SCRIPT, не отложены без исхода.

| ID | Правило | Полный контракт |
|---|---|---|
| NAME-R01 | Проекция отображения | NAME — read-only представление. | NAME-R02 | Защищённое имя | userVerified либо имя из user/personal_rule/global_rule сохраняется в рамках действующего приоритета. Стилевой каталог не отменяет личное имя. Только применимая privacy и безопасный plain-text вывод ограничивают проекцию; сохранённые значения не переписываются. |
| NAME-R03 | Исходная строка отдельно | Очищенное банковское описание доступно отдельно от короткого имени по действующему доступу и лимитам. Не подменять его словом Покупка; не требовать загрузки raw выписки/реквизитов на сервер ради имени. |

### Пошаговый алгоритм будущей проекции

1. На разрешённом серверном read path проверить owner/access/generation/deletion; выбрать существующее protected имя и доступные очищенные поля. Не раскрывать новые raw поля.
2. Применить действующую privacy к входам/выходу; masked spans не использовать как скрытый источник identity. Семантическая классификация исходного события/ownership остаётся отдельной.
3. Из уже установленного профиля/версии/периода получить допустимый merchant/service span. Противоречие/исключённый профиль не исправлять выбором первого/длиннейшего alias.
4. Отдельно определить adapter-proven служебные prefix/geo/branch/legal/channel, actual service/fulfillment/via. Без доказательства сегмент не удаляется.
5. Выбрать protected/override/same-script/source/fallback по приоритету; сохранить отличающие цифры/сервис. Не считывать guessed category как имя продавца.
6. Собрать title и qualifiers, убрать только буквальные смысловые дубли самого представления; не удалить financial event/Review. Сформировать читаемый composite для одно-поле поверхностей.
7. Валидировать лимиты/plain text/privacy/owner cache; вернуть проекцию без записи в операции/правила. Повторный вызов не читает прежний обрезанный UI-результат как единственный источник.

### Обязательная параметризация при реализации

- Все 24 merchant-направления, известные/неизвестные/одноимённые профили, физлица/юридические формы, нужный исторический период и excluded/reference/source dispositions. Style table не подмена всему catalogue.
- Кириллица/латиница/mixed, регистр/ё-е/дефисы/пробелы, зарегистрированные значимые цифры/доменные торговые формы; неизвестные идентификаторы, zero-width, буквенно-цифровые слова. Сначала privacy/provenance, не NAME-обход sanitizer.
- Типизированные сегменты против тех же слов внутри собственного имени; известный/неизвестный prefix/geo/legal/branch/acquirer. Исходные маски, URL, ФИО и обычные цифры отдельно.
- Ручное/userVerified/личное правило/global_rule assignment/auto имя; legacy merchantEquals/merchantContains/descriptionContains, alias mapping и новая style version. Matching не берётся из UI label.
- Продавец+доставка, ресторан/продукты/аптека/маркетплейс, агрегатор, самовывоз, бесплатно, отдельный курьер, отрицание/отмена/задержка, разные операции.
- Purchase/refund/transfer/fee/loan/income и supported actual status; source-local дата/profile timezone, RUB/minor units, parts вместо parent, links и независимый Review.
- Все surfaces: список/карточка/Review/search/filter/Обзор/Бюджеты/Analyzer/export; одинаковый title/composite/исходное очищенное описание и суммы без двойного учёта.
- Повторный импорт/новая покупка/reset/Undo/delete/generation/revision/entitlement/concurrent rename, чужие IDs, кэш, rollback. Новый renderer не восстанавливает данные или старую БД.
