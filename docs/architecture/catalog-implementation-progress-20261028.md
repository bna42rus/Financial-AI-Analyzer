## Что реализовано в импорте

- Добавлен отдельный `bank-source/5`. Версии /1–/4 остаются поддержанными со старой формой и поведением, включая архивный canonical mapping /4. Новая версия сохраняет допустимый merchant span в исходном алфавите, полный полезный текст, Fresh/Cloud и обычные цифры; не подставляет merchantNames поверх него.
- В /5 «Оплата услуг бюро переводов» не теряет торговое имя по substring «перевод». Денежные переводы/СБП без платёжного контекста остаются отдельными событиями, ФИО и разрешённый текст сохраняются, но merchant из ФИО не создаётся. Явный платёж через СБП отличается от перевода.
- Обычные правила privacy остаются прежними: реальные реквизиты, labelled IDs и URL маскируются до передачи и повторно проверяются сервером. Ключи/HMAC/raw/реальные выписки в тесты/логи не добавлялись.
- Если невидимый Cf был удалён privacy-sanitzer, /5 передаёт только конечную метку `textEvidence: unknown`, без исходных символов/идентификаторов. Она сохраняется при восстановлении source. Такой текст не становится доказательством нового буквального alias и не подаётся текущему model classification. Имена/описание остаются очищенными и доступными; matcher для него не включается.
- Локальные HMAC/полный source-description descriptor и правила сопоставления не менялись. /4→/5 одной и той же строки узнаётся как та же операция. Новый observation добавляется, старые observations не переписываются. Source projection собирается из реально оставшихся observations с их собственными версиями, а не наследует бессрочную копию отменённого текста.
- Legacy finite observation после /5 не русифицирует обратно унаследованный допустимый span. После удаления /5 исходная /4 или finite версия восстанавливается без ghost-профиля/неверной метки intact.
- Для /5 автоматическое merchant recognition больше не записывает красивое имя поверх `semantics.merchant`. Это сохранение matching-строки, а не готовый NAME formatter. Прежние category guards/manual/parts сохраняются.
- Import context рекламирует поддерживаемые source profiles. Новый frontend выбирает /5 только если backend его объявил; при старом backend остаётся /4. Это не авторизация клиентом: backend независимо проверяет schema/ownership/generation и прочие прежние ограничения.

NAME-I04/I05 получили конкретное исправление **нового пути /5** и адресные тесты. Это не массовая миграция старых source facts и не закрытие NAME-I01–I03/I06 или FIN-I01–I04. Неполный старый source не восстанавливается из raw/HMAC.

## Что делает компилятор

`python3 scripts/compile-merchant-catalog.py` собирает `packages/finance-core/src/catalog/generated/catalog-v1.json`; `--check` пересобирает данные в памяти и сверяет их с закоммиченным `catalog-v1.manifest.json` (SHA256/размер/входы/счётчики); если локальный JSON уже создан, сверяет и его байты. Большой JSON — воспроизводимый результат сборки; в Git сохраняются исходники, компилятор и manifest, без второй копии всех документов. Вывод детерминирован, без времени/сети/модели/БД. `python3 scripts/test-compile-merchant-catalog.py` проверяет разбор и отрицательные случаи.

Артефакт имеет схему `cashneuro-catalog-build-ir/1` и **INACTIVE_REQUIRES_TYPED_RUNTIME_GUARDS**. Это промежуточное представление полного материала, не включённые глобальные правила. Он не импортируется в клиентский bundle и не имеет права быть model context. Строки естественного языка ещё нужно превратить в адресные исполнимые guards при IMPL-03/04; compiler не делает вид, что прочитанная фраза автоматически стала корректным matcher.

Сохранены:

- все 28 исходных документов в блоках с точными строками/heading paths/SHA256; тест восстанавливает каждый исходный файл побайтно;
- 24 направления, 257 таблиц/5345 строк и 1337 блоков пояснений, включая оба набора HOME и текстовые условия вне таблиц;
- все 50 продуктовых профилей с явными finite forms, отдельные qualified source-profile references; последние не считаются числом компаний или активных identities;
- все 129 конечных source dispositions; исторические/исключённые профили не активируются;
- все 194 ACT-записи/4282 формы, 78 targets/32 routers/18 specific-sense edges, guards/composition/containment и будущие oracles;
- полный NAME: поля/приоритеты/правила/typed transforms/styles/oracles и immutable boundary.

Одинаковый NET/TEL ID из разных исходных документов не объединяет профили автоматически. Их references имеют отдельное пространство имён source document. REF/canonical binding и пригодность для конкретного платежа должны быть явными в следующем typed matcher. Таблицы внутри fenced code не превращаются в реальные записи, escaped pipe/inline-code pipe не ломают столбцы. Неверная ширина таблицы, foreign source-disposition ID, междеятельностное совпадение формы или потеря frozen corpus останавливают сборку.

## Проверки и пределы результата

Локально проходят `pnpm run check` (корневые 286 тестов, web 83, API unit 218; types/spec/build), 23 адресных source/classification теста (частично пересекаются с корневыми, не суммируются как уникальные), 3 теста компилятора и его `--check`, проверки сохранности прежнего контракта/NAME и `git diff --check`.

Три новых PostgreSQL/HTTP integration сценария включены в существующий `import-ingestion.test.ts`: /4→/5 reimport + сохранение manual name/parts/старых observations + cancellation; бюро переводов и входящий денежный перевод; отсутствие /5 capability/приёма до миграции и отказ БД для null/foreign marker/extra fields. Первый CI выявил пропущенное storage constraint расширение (179 PASS, два новых случая остановлены); добавлена миграция 0031 с закрытым enum intact/unknown и поддержкой прежних shapes. Она меняет только constraint, без UPDATE финансовых записей; установщики применяют её после backup. Backend не рекламирует и не принимает /5 до её наличия. В локальном root-only контейнере PostgreSQL не запускается под разрешённым непривилегированным UID; его защиту не обходили. Эти тесты выполняет существующий CI `assistant-candidate` на отдельном PostgreSQL 18, вместе с прежними ingestion/validation/reset/classification тестами. Фактический результат привязан к SHA в GitHub Checks; локальный PASS за них не заявляется.

Для нового CI шага добавлены проверки inactive build IR и оба новых pure source test files. Новая форма /5 закрытая: marker обязателен, downgrade /5 payload под /4 отвергается, лишнее поле не прячется за невалидной суммой, OCR не получает право на текстовые признаки.
