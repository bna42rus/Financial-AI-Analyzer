# Кандидат финансового помощника

Реализация следует согласованным контрактам [контекста](analyzer-context-contract-2-20261016.md),
[извлечения](analyzer-extraction-contract-3-20261016.md) и
[обмена/ошибок](analyzer-model-contract-4-20261016.md).

В plan/6 формат задан явно: total — общий итог, category_totals — итоги
по категориям, operation_list — строки отдельных операций. Сервер
преобразует эти значения в существующий Registry. История и текущая
подтверждённая задача используют ту же нотацию в сообщении модели.

Текущий edit каждой группы имеет приоритет над историческим. Победивший
edit выбирается до разрешения названий и литералов; уже заменённое
историческое имя не может отклонить текущий выбор пользователя.
Источники и принадлежность объектов по-прежнему проверяются сервером.

Сохранены календарь профиля пользователя, integer minor units,
независимые фильтры, фиксированная выборка и история неуспешных просьб.
Структурное исправление не может менять уже корректные значения.
Перед личным расчётом проводится проверка полноты явных условий.
Если финансовое условие осталось неразрешённым, расчёт требует уточнения.
Проверка отмечает scope каждого условия: financial либо unrelated.
Только в mixed отдельная посторонняя просьба может остаться невыполненной
без остановки финансового расчёта. Неясная дата события, порог суммы
или категория финансовой части по-прежнему требуют разрешения.
Модель получает только признак доступности выбранного периода UI,
без точных фильтров и идентификаторов. Явный выбор периода интерфейса
использует op=use_current; точный зарезервированный маркер, ошибочно
помещённый в value периода, приводится к этой же операции.
Другие поля и произвольные строки таким образом не преобразуются.
Это языковая проверка, а не формальное доказательство понимания.
Для отсутствующей категории сервер отдельно сохраняет черновик остальных
условий только после их полного разрешения и проверки доступа. Это не
успешная задача, не результат расчёта и не отвергнутый JSON. Явная команда
выбора с названным предложенным вариантом может продолжить этот черновик,
даже если модель ошибочно указала new. Самостоятельный вопрос, явный
restart и ссылка на другую задачу используют обычный маршрут. Ручные UI
изменения и фиксированный набор операций сохраняют свои приоритеты.
Черновик исключается из подтверждённой ancestry; реальный расчёт заново
проверяет доступ и получает свежие данные.

Денежный диапазон допускает словесный вид и запись через две точки.
Оба варианта сохраняют знак, общие единицы и включающие границы;
неверный порядок, лишние границы и неподдержанные единицы отклоняются.

Display text нормализуется отдельно от однострочного ввода. Допустимые
абзацы и Unicode-пробелы не являются технической ошибкой. Privacy guard
проверяет весь текст, включая реквизиты, разделённые переносом строки.
Без источников и калькулятора объяснение даётся качественно. Если модель
добавила числа или ссылки, проводится одна ограниченная правка; оставшиеся
непроверенные числовые сведения не публикуются. Это не формальная проверка
всех качественных утверждений модели. Инструкция объяснения различает
снижение, сохранение и рост покупательной способности при сравнении чистой
доходности с инфляцией и запрещает необоснованные пугающие выводы.
Содержательная оценка реального объяснения остаётся обязательной.

Проверка типов и 80 локальных software tests прошли, включая неверный new
в обоих ответах модели, UI touches, restart, независимый вопрос, подлинных
родителей, смешанные просьбы, неразрешённые финансовые условия,
выбранный период интерфейса без передачи его фильтров модели, Unicode/абзацы и ограничение неподтверждённых числовых примеров.
Это проверки программы на синтетических ответах, а не новая точность
реальной модели.
Исторический frozen executable binding не изменён; эталоны не подставляются
вместо ошибочных предыдущих результатов.

Новый протокол требует отдельной языковой приёмки. HTTP/PostgreSQL и UI
подключены только к изолированному test provider для программной проверки;
подробности в [описании runtime](analyzer-assistant-runtime-20261016.md).
Реальный провайдер на развёрнутом стенде, Production и автоматические
изменения пользовательских данных не включены.
Полная продуктовая, браузерная и нагрузочная приёмка остаются незавершёнными.
Служебные параметры операторского запуска в этот документ не включены.
