# Новый кандидат финансового помощника — 16.10.2026

Контракты [контекста №2](analyzer-context-contract-2-20261016.md),
[извлечения №3](analyzer-extraction-contract-3-20261016.md) и
[обмена/ошибок №4](analyzer-model-contract-4-20261016.md) согласованы владельцем.
Реализован отдельный исполняемый кандидат и операторское испытание.
Клиентский маршрут и Production не включены. Первая версия выполнила 5/20
сообщений: 3 прошли, затем выявлены дефект freshness-флага и ошибки изменений
контекста. Новый plan/2 ещё не проверен на реальной модели. Исторический
результат старого intent эксперимента остаётся 46/88.

## Что работает в коде

- Закрытый plan/2, шесть финансовых/посторонних маршрутов, field-specific
  типы. Нет обязательного дублирования периода в quote/value или словаря
  evidence для grouping/metric. Неизвестные поля/UUID/SQL не разрешаются.
- Очищенные пользовательские сообщения, отдельная подтверждённая task book,
  история неуспешных просьб. Несколько неуспешных сообщений можно заново
  разобрать вместе; failed JSON не передаётся следующему вызову.
- Часовой пояс передаёт сервер из профиля. Сегодня и текущий месяц
  вычисляются по нему; date-only банковские даты не сдвигаются. Нет
  резервного Moscow timezone. Начальное заполнение профиля из браузера
  ещё требует подключения к пользовательскому маршруту.
- Уточнение отсутствующей категории: ограниченный список собственных
  названий доступен модели только после положительного финансового
  маршрута. Предложение проверяется по этому списку; похожая категория
  не применяется и не создаётся автоматически. Следующий явный выбор
  названия переосмысливает pending просьбу.
- Существующий серверный контекст сохраняет независимые фильтры,
  UI touches, происхождение и фиксированную выборку. Даты и суммы
  компилируются программой, деньги считаются integer minor units.
- Один основной вызов; максимум три завершения на сообщение, включая
  максимум одно исправление структуры. Пропуски смысловых условий
  автоматическим repair не исправляются.
- Отдельные query/answer/clarification/unsupported/redirect/error.
  Общие объяснения не читают операции; актуальная ставка без подключённого
  поиска получает честное сообщение о недоступности источника.
- Приватные fsync receipts: reserve и sent до POST, usage до разбора
  результата. Известный результат воспроизводится без нового POST.
  Готовый commit payload сохраняется до атомарного idempotent commit;
  обрыв на этой границе не требует снова обращаться к модели.
- Независимый бюджет: полный context reservation, целочисленные atoms,
  сохранённые unknown holds, отсутствие новых вызовов при unknown delivery,
  проверка model identity/границ usage. Старый ledger не открывается.

## Проверено и ещё не проверено

28 новых software tests: 18 поведения, 8 HTTP/файлов/стоимости и 2
испытательного стенда. Вместе с 35 релевантными старыми проверками —
63/63. Проверены противоположные стороны полуночи, DST, восстановление
двух неуспешных просьб, сохранение условий, выбор отсутствующей категории,
неоплачиваемый replay, crash у commit, malformed JSON с известным usage,
смена модели, unknown delivery, пределы бюджета и закрытые файлы/locks.
TypeScript strict/noUncheckedIndexedAccess для новых файлов и их import
closure проходит. Эти числа относятся к программе, не к точности нейросети.

Frozen executable binding прежнего intent испытания неизменен:
`0167d21fd279fa1df5cac60df29fa86f6966a164f270dff5e636cf6cb0e1e4fa`.
Старые raw ответы/операторская выгрузка в новый commit не включаются.

Новый development smoke содержит 20 заранее заданных синтетических
пользовательских сообщений, точные queries/filters/parents/итоги,
два часовых пояса и выбор «Общественного транспорта» при отсутствии
«Такси». Даже совпавший total не скрывает неправильный фильтр.
Это открытый начальный smoke, не независимый holdout и не приёмка PDF.
Общие текстовые объяснения дополнительно требуют смысловой оценки;
автоматический PASS проверяет только маршрут/формат для таких случаев.
Предыдущие неверные результаты не подменяются эталонными родителями.

Пока отсутствуют реальное языковое измерение этого кандидата, подключение
к текущему REST/UI, транзакционный production adapter, настоящий поиск,
полная приёмка сценариев из PDF, E2E и нагрузочная проверка. Файловый
adapter предназначен для изолированного операторского опыта. Поддержан
существующий Registry (expenses/income/attention, none/category/operation,
previous_same); остальные инструменты честно недоступны. Текст обычного
постороннего перенаправления пока фиксированный и вежливый.

## Подготовленный операторский опыт

Стенд: `apps/api/src/assistant-trial-main.ts`. Node 24, без установки зависимостей.

| Режим | Действие |
|---|---|
| `--prepare` | Source binding, число случаев, предложенный тариф/лимит; HTTP=0, POST=0 |
| `--inspect` | Один GET каталога Cloud.ru; только безопасные metadata; POST=0 |
| `--live --within-original-cap-rub=10` | Повтор 20 сообщений на plan/2 в остатке прежних 10 RUB и 60 вызовов |
| `--report` | Человеческий отчёт сохранённых результатов; HTTP=0, POST=0 |

Live версии 2 использует уже согласованный общий лимит 10 RUB.
Он читает budget первой версии без изменения, проверяет integrity/usage,
вычитает фактический расход и число вызовов; unknown hold запрещает старт.
SHA предыдущего budget закрепляется в новом permit и проверяется перед POST.
Новые 10 RUB сверху не добавляются. На 16.10.2026
публичный [каталог Cloud.ru](https://cloud.ru/products/evolution-ai-factory/catalog-foundation-models)
указывает gpt-oss-120b: 15.86/61 RUB за миллион input/output tokens,
контекст 131K. Проверено 16.10.2026 в 10:45 UTC; после 24 часов live
отказывается работать до новой проверки тарифа. Перед live один GET
проверяет точный ID и context metadata; SHA metadata фиксируется в permit.
API model ID остаётся mutable alias, неизменяемый snapshot провайдером
не доказан. Runtime model/usage drift останавливает опыт.

Новый путь `/var/lib/cashneuro/analyzer-assistant-smoke-v2` (0700),
budget и квитанции 0600. Исторические smoke-ledger/frozen/cache не открываются. Budget попытки
assistant-smoke-v1 читается только для вычитания уже использованного лимита.
При первой технической ошибке либо третьем провале проверки опыт
останавливается для разбора. Повтор live-команды всегда report-only,
если budget уже создан, включая незавершённый опыт. Stale locks и
неизвестные резервы автоматически не удаляются. Даже после разбора
продолжение требует нового явного действия, бюджет сам не повышается.

Скрипт `run-assistant-smoke-20261016.sh` получает reviewed commit и режим.
Он архивирует pinned Git source в отдельный root-owned каталог, выполняет
локальные проверки и выбранный режим; секретный ключ не печатается.
Сохранённые ответы синтетические; итоговый консольный отчёт можно передать
в чат обычным текстом. Для смыслового разбора полного объяснения/плана
нужны также нужные сохранённые ответы, а не одно число PASS.

## Исправления plan/2 после первого прогона

- Булевый needsFreshSources влияет только на explain. Безвредный default
  в read не вызывает платный repair; закрытая schema и parser согласованы.
- activeTask явно отделён от текущего question. Prompt извлекает минимальные
  изменения из question; история нужна для связи, а не копирования фильтров.
- При продолжении со сбросом none/clear либо новом amount-only плане при
  существующей задаче выполняется check_changes: отдельная смысловая
  проверка по текущей просьбе. Это дополнительный оплачиваемый вызов внутри
  прежнего максимума три, а не структурный repair или доказательство истины.
- Структурный repair допускается для shape/JSON, но не для семантических
  конфликтов. Поля, уже прошедшие field schema, блокируются по значениям;
  изменение их моделью завершает запрос ASSISTANT_REPAIR_MEANING_CHANGED.
- Новые tests проверяют эти механизмы на самостоятельно заданных синтетических
  вариантах. Реальные operator raw ответы в Git не публикуются.
