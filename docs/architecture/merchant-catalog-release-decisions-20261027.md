## 3. Что означают конечные состояния источников

- **PROFILE_CONFIRMED:** первичный профиль продавца/сервиса найден в указанном объёме. Bank/source identity, конкретная услуга, дата и роль всё равно по фактам операции; сайт не удостоверяет каждый alias.
- **PROFILE_CONTEXT_ONLY:** доказан бренд/институт/продукт/регион, но не единый merchant всех похожих строк. Точный контекст/получатель/предмет необходимы; это закрытое условие допуска, не TODO источника.
- **REF_PROFILE:** тот же ранее заданный профиль; не новый оператор/счёт/расход.
- **HISTORICAL_CONTEXT_ONLY:** достаточно для доказанной истории в указанном контексте; новая текущая глобальная identity не активируется по старой марке/домену.
- **GENERIC_ACTIVITY_ONLY:** родовое описание деятельности, не единый бренд (например Белорусская косметика).
- **EXCLUDED_FROM_ACTIVE_V1:** окончательно вне нового общего активируемого словаря v1. Нет достаточного первичного основания либо найден другой оператор/припаркованный домен. Это не утверждение «компания закрылась» и не удаление пользовательской операции/ручного правила.

Условия применяются также ко всем REF-копиям указанного профиля. Похожая буква/новый найденный сайт/одноимённый производитель не заменяют старую identity. Где один источник строже другого, незаметного повышения нет. Для остальных датированных первичных SRC/IDX/REG исходного корпуса сохраняются ограничения; международный профиль не обещает доступность оплаты из РФ, HIST не превращается в нынешнего оператора, MEDIA/неподтверждённый источник сам не разрешает новый безусловный merchant-match. Достаточное фактическое назначение услуги/личное правило может определять категорию независимо от недоказанного бренда.

Все наблюдавшиеся попытки ограничены публичными страницами/собственными документами/реестрами/профилями непосредственных участников. **Ставки/цены/сроки/реквизиты/персональные документы не копируются в правила.** Для ФКР исторический официальный городской документ подтверждает имя/жилищный профиль, не нынешние реквизиты или цену. Для ГИБДД городской портал различает органы/основания штрафов, не используется похожий неустановленный gov-gibdd-домен. Для VK Donut первичная схема API подтверждает subscriptions, не тариф/смысл всех донатов. Для банковских aliases сохраняется отдельная будущая проверка, а не фиктивный статус «встречалось в банке».

## 6. Полностью определённое поведение без выдумывания данных

1. **Очевидная услуга:** достаточная identity + обычная установленная оплата + доступный совместимый узел → нормальное назначение без лишнего Review из-за отсутствия чека/модели телефона/маршрута/текста документа.
2. **Реальная неоднозначность:** обоснованная предварительная категория + видимое «Стоит проверить» с конкретной причиной; category/role/link/duplicate независимы. Прежние специальные Яндекс Go/Заправки/Парковки России сохраняются.
3. **Нет оснований/противоречие/нет нужной доступной категории:** сохранённые source/merchant/деятельность, определённый безопасный исход без вымышленной категории/роли/чужого ID; разрешённый выбор без блокировки импорта. Это обработанный вход, а не отсутствующее правило.
4. **Многопрофильные услуги/суммы:** известный предмет/цель/состав выше бренда; parts только по реальным суммам, вместо parent, без новых банковских операций из счёта/прайса/рекламного кабинета.
5. **Приватность:** разрешённые ФИО/обычные цифры/слово перевод не blanket-mask; карты/счета/договоры/телефоны/email/паспорт/URL и маркированные коды/ИНН/БИК остаются закрыты. Никаких текстов дел/документов/данных телефонов/клиентских баз в AI.
6. **Границы полномочий:** server ownership/status/entitlement/deletion/revision до preview/commit, closed Registry; HMAC/SQL/admin/password/sessions не AI. Личные verified/правила/parts/links/source/dedupe не перезаписываются общим справочником.
7. **Финансовая модель:** RUB/integer minor/source-local даты, profile today, source-user-effective, credit/loan/refund/links/allocations по PDF; одинаковый расчёт в интерфейсах/Analyzer. Продавец/услуга не меняют роль без основания.
