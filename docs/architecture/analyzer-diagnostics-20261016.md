## Запуск

`run-intent-diagnostics-20261016.sh <точный commit диагностики>` создаёт новый
временный checkout на VPS и использует уже установленные dependencies.
Старые checkouts не перезаписываются. Скрипт сначала выполняет пять software
tests нового диагностического кода, затем запускает read-only CLI с sudo.

CLI использует существующий экспортёр только как приватный дочерний процесс.
Закодированный блок не выводится владельцу. Сохраняются все его проверки:
753 ledger records/head, frozen/hash, receipt/cache wire hash, AES-GCM integrity,
88 IDs/23 rejects, private permissions и запрет отражённых ключей. Экспортёр
не изменён. Нет API key аргументов, HTTP, резервов, paid retry или снятия holds.

Дополнительная offline проверка требует неизменённого executable binding
0167d21fd279fa1df5cac60df29fa86f6966a164f270dff5e636cf6cb0e1e4fa,
восстанавливает каждое исходное тело запроса и сверяет его wire SHA. Ответы,
которые были отклонены, остаются отклонёнными при подсчёте. В компилятор и
контекст не подставляются исправленные ответы или golden parents. Нет чтения
28 holdout ответов или попыток продолжить четыре невыполненных повтора.

Для публикации исторического отчёта CLI требует воспроизвести ровно 46/88,
23 отказа и 4.333490020 RUB. Несовпадение останавливает диагностику понятным
фиксированным кодом; это не повод менять эталоны. При изменении ledger/head
операторская выгрузка также остановится, а не ослабит проверку.

## Отчёт

Консоль показывает сводку и подробности каждого неуспешного случая. Отдельный
`ai-diagnostics-full.txt` в новом checkout содержит все 88 случаев, в том числе
успешные: вопрос, исходный JSON, эталон, точный этап/код/поле отказа, compiler
proposal, фактический запрос, неверные поля, предыдущие задачи, tokens/cost.
Файл создаётся эксклюзивно с 0600; существующий файл не заменяется.

Категории описывают наблюдение, а не выдуманную первопричину. В частности:

- VALIDATION_REJECTION: воспроизведён отказ parser/validator. Правильность
  смысла raw ответа отдельно оценивает проверяющий, в том числе склонения
  имён, точность цитат и ограничивающие regex. Не все 23 — ошибки relevance.
- MODEL_RELEVANCE_MISMATCH: принятый модельный relevance отличается от
  исторического эталона. Новый контракт тематики может потребовать иных тестов.
- COMPILER_REJECTION: raw прошёл parser, compiler выбросил показанный код.
- TASK_CONTEXT_UNRESOLVED: исходный workflow вернул task_missing.
- RESULT_MISMATCH_REQUIRES_REVIEW: неверный результат требует сопоставления
  raw, compiler proposal, связи и фактического состояния.

earlierFailure и неуспешный ожидаемый родитель показываются отдельно. Ни один
флаг сам по себе не доказывает каскадную причинность. Выгрузка содержит уже
разобранные JSON values, а не оригинальные HTTP bytes/reasoning. Нельзя
утверждать, что новый инструмент восстановил отсутствующую HTTP-переписку.
