# Staging: постоянный ИИ с месячным пределом 100 ₽

Владелец 1 ноября 2026 года выбрал 100 ₽ в месяц для своего тестового аккаунта
вместо суточного допуска и суммарного ограничения 70 техническими вызовами.
Это разрешение на расходы приложения в пределах бюджета, а не подтверждение
пополнения баланса Cloud.ru и не изменение будущих пользовательских тарифов.

## Режим

Новый явный флаг установщика `--resume-ai --monthly-ai-budget=100` добавляет
версионированную monthly-authority в root-only конфигурацию. Разрешён ровно
один прежний тестовый аккаунт Staging/Finance, прежний ключ и project ID.
Production недоступен. Все поля прежнего допуска, расходы, счётчики и квитанции
сохраняются. Без этого флага обычное продление не может добавить monthly-mode.

Месячный **операционный** предел считается от первого числа до первого числа
по Москве; общий расход включает Assistant и оплачиваемую системой
категоризацию этого тестового аккаунта. Суммируются квитанции по дате dispatch,
в том числе из прежних коротких тестовых периодов текущего месяца. Повторная
установка не выдаёт новый бюджет. Зарезервированные суммы тоже занимают бюджет.

Это отдельный технический предел: по PDF 29.2 автоматическая категоризация
по-прежнему не списывает пользовательскую quota/себестоимость. Пользовательские
task quotas и их границы по access cycle (PDF 29.4) этим изменением не меняются.
Остаток операционного бюджета и предупреждения 80/95/100% видны в Анализаторе.

Каждая резервация сериализуется advisory-lock по проекту, до `reserveCost`.
После резервирования проверяется совокупный месячный расход; отказ откатывает
всю транзакцию до HTTP. Незакрытая квитанция и provider freeze блокируют новые
вызовы и после смены месяца. Учёт фактического перерасхода при нарушении
контракта провайдером сохраняется, затем дальнейшие вызовы блокируются.

Суточного отключения и общего предела 70 в monthly-mode нет. При устаревшем
тарифе перед модельным запросом автоматически выполняется публичный GET
прежнего официального PDF; проверяется утверждённый SHA256. Изменение тарифа
или недоступность проверки останавливает dispatch до резервации/POST.
Оплачиваемые запросы не повторяются автоматически. Переход периода не требует
перезапуска сервиса; один dispatch использует один снимок cost policy.

## Установка и откат

Штатная установка по точному SHA проверяет сохранённые два синтетических PASS
и их оплаченные квитанции; установка не посылает новых модельных POST.
Сохраняется точный предыдущий root config. При первом переходе старому runtime
для отката возвращается исходная конфигурация без неизвестного ему monthly-mode.
Истёкший прежний допуск откатывается в паузу штатным механизмом установщика.

На момент подготовки кода установка monthly-mode на сервере не подтверждена.
Пополнение Cloud.ru не выполнялось: доступный браузер не загрузил кабинет.

## Проверки

- Модульные: сохранение истории/authority, один аккаунт, запрет Production,
  будущей даты и другой суммы; отсутствие суточного срока, Московские границы
  месяцев/года/високосного февраля, GET-refresh с одновременными запросами и
  остановка до POST при неверном тарифе.
- PostgreSQL: совокупный предел с прежним trial spend, конкурентная резервация,
  откат при исчерпании, более 70 небольших вызовов, перенос неизвестного резерва
  и provider freeze через границу месяца; классификация не расходует user budget.
- Установщик: отдельное разрешение 100 ₽, неизменность истории и rollback.
- Desktop/mobile: остаток в рублях и предупреждение независимы от task quota.

Все проверки используют синтетику; production-данные и платные вызовы не нужны.
