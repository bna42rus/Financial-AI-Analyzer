Основание: полный PDF 18–20, 25, 35.1–35.6, 49.2–49.4 и 53.7; A-02/A-05/A-06/A-08, B-02/B-03/B-07/B-08/B-09. Оригиналы PDF/Word и baseline 1.3 не изменяются. ## Распознавание и локальный HMAC

Новый профиль `bank-source/2` и adapter `bank-pdf/2` сохраняют закрытые event/merchant codes, расширяют справочник с 6 до 20 canonical labels и поддерживают дополнительные явные русские/английские payment/refund prefixes. Корпус искусственных описаний проверяет aliases/case, знаки, transfer/recipient/mixed-event evidence, полные и объединённые PDF columns. Справочник обозначает бренд, не юридическое лицо/конкретный филиал; категории и связи из названия не назначаются. Неизвестные магазины сохраняют достоверный event при наличии явного префикса, а название остаётся пустым до решения пользователя.

Полное описание временно остаётся на устройстве. NFKC/case/whitespace нормализация сохраняет отличия документальных и terminal/auth tokens. WebCrypto HMAC по стабильному per-user key, bank и keyed account alias создаёт `descriptionHmac`; сервер получает только 64 hex digits или явный null. Нормализованное описание, имена, реквизиты и исходные identifiers не добавляются в payload, source label, report, telemetry или AI. Старые `text-free/1` и `bank-source/1` остаются допустимыми со своими прежними закрытыми полями/codes. Новый field обязателен только в версии 2; malformed/extra fields проверяются даже при невалидной дате/сумме. Пароли и raw files остаются локальными.

`strict-bank-description/2` использует exact source instant, account alias, posted-date precision/value, signed amount, RUB, direction и полный keyed description identity. Он не заменяет stable bank ID и не использует исправленные пользователем effective значения. Неизвестный merchant может иметь достаточный строгий fingerprint без раскрытия текста. Date-only/unsafe/missing descriptions не дают автоматического match. Полный description identity отличает покупки с одинаковыми брендом, временем и суммой. При двух одинаковых source instances действует one-to-one; несколько подходящих canonical operations остаются неоднозначными. Исторический finite fingerprint остаётся версионированным и не подменяется новым.

Possible Duplicate учитывает различие полных description identities, когда они известны с обеих сторон; legacy/отсутствующие identities не считаются доказательством различия. Новая сигнатура не является fuzzy matching или полной совместимостью описаний между разными формами банка. Смена динамических tokens может уменьшить число автоматических совпадений; безопасного угадывания/удаления нет. Решения «разные операции» и canonical merge по-прежнему используют существующие tenant-scoped IDs/provenance.

Digest хранится только в ingestion row рядом с source evidence; исходное описание не хранится. Cancellation/deletion/reset удаляют его существующими provenance cascades. При отмене одного shared source оставшийся observation и его identity сохраняются. Интерфейс, import reports и AI не получают этот digest.

## Групповое решение в Review

Предложение ищет похожие отрицательные purchase operations только внутри сохранённого fixed set сессии. Совпадают непустой merchant, account, kind/role/category/subcategory/counterparty values и user verification, участие в аналитике и активные classification review reasons. Resolved/missing, duplicates, transfers/refunds, отдельные части и link/dependency conflicts не попадают в предложение. Разные суммы допустимы и показываются пользователю. Ограничение сессии 1000 не обрезается молча.

Кнопка открывает точный список с датами/суммами и объяснением сходства. До применения пользователь может закрыть предложение без финансовой записи. Форма фиксирует IDs и finance epoch; новые импорты не расширяют список. После изменения данных требуется закрыть и заново показать группу, без rebase старого состава. Новые операции продолжают отображаться в общих attention counts, но не входят в эту Review session.

Групповое решение использует существующий атомарный bulk command с `reviewScope` (session ID/revision/current anchor). Backend проверяет own session, in-progress/current anchor, session revision и точное равенство предлагаемого набора при preview и повторно при commit. Смена cursor/status на другом устройстве отвергает старую команду даже при неизменившемся finance revision. Финансовые права/generation/revision/dependencies сохраняют существующую серверную проверку. Никакая новая публичная authority/SQL/AI возможность не вводится.

После явного submit решение применяется сразу, как предусмотрено Review. Один action ID защищает network retry, один History delta позволяет общий Undo, bank facts не меняются. Независимые причины/verification не снимаются случайно. Persisted progress пропускает действительно решённые операции; Undo возвращает причины и позволяет новый разбор нерешённых.

## Миграция, проверки и границы

Миграция 0017 выполняется после 0001–0016 отдельным Development operator connection: `pnpm --filter @finance/api operator migrate-import-description-identity` при существующих `APP_ENV=development`/`MIGRATION_DATABASE_URL`. Добавляются nullable `description_hmac`, closed finite-source CHECK и imported-only constraint. Runtime tenant grants/RLS неизменны; raw текст не backfill-ится. Изменение схемы additive/forward-only; колонку и расширенный CHECK не удаляют при откате. До первого profile/2 импорта возможен прежний runtime. После появления новых merchant codes/evidence нужен compatibility build, понимающий версии 1/2, либо forward-fix: старый reader/worker не знает новые codes. Перед сменой runtime остановите новые импорты и завершите accepted jobs совместимой версией. Перед Staging нужны migration/restore rehearsal и проверка grants/cleanup.

Локально проверяются core/import privacy/identity/group selection, strict types, UI unit tests, сборки и источник спецификации. PostgreSQL/HTTP проверяют expanded/unknown descriptions, strict/date-only matching, remembered decisions, source retention/deletion, group fixed scope/foreign scope/atomicity/idempotency/Undo и session conflict после preview. Реальный HTTP/PG browser journey проверяет lost acknowledgement и общий Undo на desktop/mobile. UI screenshot фиксирует точный scope и stale reopening на обеих ширинах; artifact `review-group-previews` сохраняется CI на 7 дней. Реальные bank/device/Staging проверки не заменяются искусственным corpus.

Остаются CSV/XLSX/OCR, arbitrary sanitized merchant descriptions/unknown-format AI, fuzzy/date-only quality corpus, полный classification/link final pass, natural-language AI Review/Registry, budgets/views/widgets и provider/owner/release acceptance. Этот блок не объединяет цепочку с main, не покупает услуги и не выпускает Production.
