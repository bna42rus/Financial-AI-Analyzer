# Импорт и обзор: правки 31 октября 2026

Основание: 11 пунктов владельца после установки de198482. Старая схема JSON и сохранённые представления продолжают читаться. Денежные расчёты, банковские факты и журнал платных запросов не переписываются.

## Порядок работы

1. Импорт: убрать повторный выбор того же файла внутри открытого окна; новое открытие допускает повтор. Завершённое уведомление закрывается через 15 секунд, незавершённые ошибки доступны в истории.
2. Обновление: опрашивать статус импорта отдельно от финансового экрана. Экран обновляется по явной кнопке, переходу, повторному входу и собственным подтверждённым изменениям. Фильтры остаются рабочими.
3. Тексты: краткое правдивое объяснение зашифрованного соединения, настоящее время для OCR. Нельзя называть маскирование шифрованием хранимых полей.
4. Фокус фильтров: внутренняя видимая рамка без увеличения размеров.
5. Итоги: один раскрывающийся заголовок, формулы и визуально разделённые суммы/счётчики; убрать дубли фильтров и служебные пояснения.
6. ИИ-категоризация: постоянный видимый вход, доступность запуска внутри меню по существующим серверным основаниям. Не менять блокировку неизвестного платного запроса.
7. Полотно: плавное перемещение карточки, анимация перестановки соседей, произвольные ограниченные ширина/высота, клавиатура и телефон; размеры компьютера и телефона сохраняются отдельно.
8. Виджеты: добавить прямо с полотна, иконка настройки, общая фиксированная палитра 50 цветов, убрать «Как рассчитан виджет».
9. Конструктор: название отдельно сверху; сброс текущего черновика к открытой конфигурации; условный шаг времени; график всегда, таблица значений отдельно без ограничения числом групп графика; чекбоксы метрик максимум три.
10. Время: все пустые интервалы внутри применимого диапазона; для всей истории — границы выписок, слишком широкий охватывающий диапазон ограничивается ими. Не сдвигать даты банковских операций.
11. Даты: год из четырёх цифр во всех пользовательских датах. Проверить ввод с клавиатуры, вставку и календарь.

## Отдельное последующее согласование

- «Сбросить» в черновике виджета/представления возвращает последнее применённое состояние до текущего редактирования. «По умолчанию» явно возвращает заводскую конфигурацию. Сброс фильтров снимает ограничения. Не превращать финансовый сброс/удаление в отмену черновика.
- Полный набор метрик и совместимые сочетания обсудить отдельно; сейчас сохранить существующие денежные смыслы. Бюджеты остаются отдельной метрикой, максимум три остальных; разные единицы отображать на разных осях.
- «Получатель / магазин» объединяет повторные покупки в одном месте; «Операция» показывает каждую покупку отдельно. Объединять эти группировки нельзя.

## Установка после истечения допуска ИИ

Новый флаг установщика `--keep-ai-paused` допускает обновление Web/API при уже истёкшем сроке платной модели. Он запрещён вместе с продлением/платной проверкой, не меняет сроки, цены, лимиты, allowlist и историю; выключает модель и автоматическую категоризацию в команде сервиса. Настройки получают только привязку к новому исходному коду. Обратное переключение тоже оставляет истёкший ИИ выключенным, чтобы прежний API мог запуститься; точная исходная команда сохранена отдельно. Возобновление модели — отдельная процедура после сверки неизвестного запроса. Все справочники, правила и точные расчёты без модели остаются доступны.

## Исправление подготовки резервной копии

Попытка установки 676c09e92447 остановилась на `FileExistsError` до переключения служб. `snapshot` уже создавал приватный файл `dropin`, а ветка паузы повторно вызывала для него `private_write` с `O_EXCL`. Теперь эта ветка атомарно заменяет только созданную резервную копию, сохраняя точный исходник в `dropin.original`. Каталог каждой подготовки выделяется через `mkdtemp`, поэтому повторная попытка не перезаписывает прежние копии и не зависит от секундного timestamp. Добавлены проверки с реальным файловым вводом-выводом, правами 0700/0600 и запретом вызовов служб на этапе подготовки. 12 тестов обновления и 8 тестов установки прошли. Код Web/API, миграции и runtime SHA256 не изменены; платных вызовов 0.

## Исправление проверки API и согласованные кнопки

В следующей попытке владелец получил `API_HEALTH_FAILED` с автоматическим откатом. Причина в коде установщика: обе проверки после переключения безусловно требовали `assistant=cashneuro-assistant-workflow/7`, тогда как HTTP `/health` намеренно не возвращает `assistant`, если модель выключена. Проверка теперь зависит от выбранного режима: для выключенной модели нужны `status=ok`, `profile=finance` и отсутствие включённого помощника; для включённой по-прежнему требуется точная версия workflow. Независимо от модели проверяется точный `WorkingDirectory` кандидата. Ожидание API сообщает о ходе проверки, а не молчит минуту.

«Сбросить» в редакторах отменяет несохранённые правки. Новая отдельная кнопка «По умолчанию» в представлении возвращает стандартные виджеты, оба расположения и все даты, сохраняя имя/идентичность выбранного представления; это только черновик до явного сохранения. В виджете «По умолчанию» возвращает стандартные параметры графика, сохраняя текущее имя и выбранные метрики. «Сбросить» после этого всё ещё возвращает исходное состояние редактора. Заводское оформление и стартовые настройки теперь явно называются «… по умолчанию». Фильтры очищаются прежней кнопкой «Сбросить»; финансовое удаление не изменено.

## Явное возобновление ИИ

По новому поручению владельца добавлен `--resume-ai` совместно с проверенными сохранёнными свидетельствами и точным SHA256 runtime. Используется существующая проверка квитанций, актуального официального тарифа, модели и переноса использованного бюджета. Установщик не отправляет модельных POST и не увеличивает исходные денежный лимит и число вызовов. При успехе включаются оба флага помощника/категоризации, в том числе после ранее сохранённой паузы. Откат после неудачного продления не включает истёкшие полномочия.

Если в БД остаётся неопределённый платный запрос или исходный лимит исчерпан, ИИ не объявляется возобновлённым. Интерфейс и обычные расчёты устанавливаются отдельно с выключенной моделью, результат содержит `aiResumeBlocker`, затем запускается ограниченная по времени диагностика без платных запросов. Резерв, исходная квитанция, статус unknown и счётчик вызовов сохраняются. Для неизвестного расхода нужны действительные данные провайдера; резерв нельзя выдавать за фактическое списание, обнулять или автоматически повторять запрос.
