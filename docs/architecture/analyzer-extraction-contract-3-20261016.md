# Контракт №3: понимание намерения и параметров — согласован 16.10.2026

Статус: владелец согласовал правила 16.10.2026 с двумя поправками: часовой
пояс пользователя и предложение близких категорий при отсутствии точной.
Контракты тематики №1 и контекста №2 также согласованы. Этот документ
описывает смысл, а не новый JSON, промпт, число API-вызовов или разрешение
на действия. Правила ещё не полностью реализованы и не измерены моделью.

## Согласованные правила

1. **Учитывать все явно названные условия.** Период, категория, счёт,
   магазин, сумма, формат и сравнение извлекаются независимо. Нельзя
   пропустить одно условие и молча выполнить более широкий расчёт. Нет
   нового указания — применяется контракт контекста №2. Отсутствие даты в
   самостоятельном вопросе само по себе не требует уточнения: есть UI defaults.
2. **Понимать смысл, сохранять исходную просьбу.** Регистр, обычные формы
   слов и наличие предлога не должны менять финансовый смысл. Служебное
   доказательство параметра не должно превращать корректный вопрос в отказ
   только из-за заглавной буквы. Нормализация не даёт права менять выбранную
   категорию, число, знак, даты, отрицание или степень сравнения. Выдуманная
   отмена/новое условие запрещены. Точный формат evidence согласуется в №4.
3. **Даты вычисляет программа по часовому поясу пользователя.** Используется
   сохранённый profile timezone; первоначально он определяется из браузера
   и может быть изменён пользователем, как в PDF 33.7. Серверное текущее
   время переводится в этот пояс. Модель не выбирает пояс по языку/стране
   и не подставляет Москву. Сегодня — локальная текущая дата, вчера —
   предыдущая. Текущий месяц —
   с первого числа по сегодня. Предыдущий месяц — полный календарный месяц.
   Именованный месяц — полный месяц; без года — текущий год, если слова
   пользователя не задают другой. Явный диапазон включает обе границы;
   противоречащие границы требуют уточнения. Скользящий период и полные
   календарные месяцы различаются. Событийный период, который нельзя
   надёжно установить (например, привязку к неизвестному поступлению),
   нельзя заменять выбранным периодом — нужно уточнение.
   Даты без времени из банковской выписки не сдвигаются при смене пояса.
   Смена profile timezone не переписывает уже определённые оплаченные
   access/quota boundaries; этот контракт не изменяет commerce calendar.
   Если профиль ещё не содержит проверенного пояса, его нужно определить
   и сохранить до относительного расчёта, а не молча выбрать Москву.
4. **Названия разрешаются в личном каталоге.** Явная категория/подкатегория
   выбирается как категория, не подменяется магазином. Магазин и контрагент
   — самостоятельные условия. Обычные формы написания должны сопоставляться
   с названиями и подтверждёнными псевдонимами. Неизвестное название не
   означает все категории или отсутствие фильтра. При нескольких подходящих
   объектах, которые контекст не различает, требуется короткое уточнение.
   Программа проверяет существование и принадлежность объектов пользователю.
   Если точной категории нет, помощник ищет смысловые варианты среди
   существующих пользовательских названий и предлагает подходящие, явно
   называя отличие. Например: «Категории “Такси” нет. Есть “Общественный
   транспорт”. Посмотреть эту категорию?» Близость по смыслу не делает
   категории равнозначными: такой вариант нельзя молча применить вместо
   запроса или выдать его сумму за расходы именно на такси. При отсутствии
   разумного варианта сообщить это. Новая категория и постоянный псевдоним
   не создаются автоматически; действия регулирует отдельный контракт.
5. **Смысл суммы однозначен.** По умолчанию обычный положительный порог
   суммы операции относится к её модулю, а не знаку и не итогу отчёта.
   Явная знаковая/отрицательная сумма сохраняет знак. Рубли и копейки
   переводит программа в целые копейки. «Больше 1000» исключает ровно 1000,
   «не меньше 1000» включает; «не выше 99 рублей 50 копеек» включает 99.50.
   Условие части операции не подменяется порогом полной операции. Если для
   части пока нет инструмента, помощник объясняет отсутствие функции.
   Неясные единицы/валюта или противоречащий диапазон не угадываются.
6. **Формат отделён от отбора.** Просьба суммы остаётся суммой, даже если
   содержит слово «операции». Явный список операций — список. Разбивка
   по категориям меняет формат, сохраняя фильтры. Запрошенные top-N,
   сортировка и группировка не должны пропадать. Если нужный инструмент
   пока отсутствует, помощник сообщает об этом вместо похожего расчёта.
   При отсутствии указания программа/помощник выбирает понятный формат
   по существующим правилам, не добавляя отбор по данным.
7. **Сравнение — отдельное условие.** Указанные периоды/категории сравнения
   берутся из вопроса и контекста. Предыдущий такой же период вычисляет
   программа. Смена категории/формата сама не отменяет сравнение. Явное
   «без сравнения» снимает только его. Нельзя придумывать такое указание.
8. **Четыре разных исхода.** Понятный поддержанный запрос выполняется;
   реальная смысловая неоднозначность вызывает короткое уточнение;
   отсутствие финансового инструмента объясняется как отсутствие функции;
   технический сбой сообщается как технический. Последние три не являются
   посторонней темой и не получают шутливое перенаправление. Список реально
   доступных инструментов принадлежит программе, а не обещанию модели.

## Согласованные примеры

| Просьба | Ожидаемый смысл | Недопустимая подмена |
|---|---|---|
| Сколько потратил сегодня? | Расходы за текущую дату в profile timezone пользователя | Расходы за весь выбранный месяц |
| Сумма расходов на продукты за сентябрь | Сумма, продукты, полный сентябрь | Снять категорию или отказать из-за регистра слова |
| Сумма доходов по операциям больше 1000 рублей | Общий доход по операциям с модулем суммы строго больше 1000 | Выдать список только из-за слова «операции» |
| Покажи операции не выше 99 рублей 50 копеек | Список и включающий верхний порог 99.50 | Порог компонента вместо операции |
| На такси, но такой категории нет, а есть Общественный транспорт | Назвать отсутствие точной категории и предложить имеющийся вариант для выбора | Молча приравнять общественный транспорт к такси |
| По категории с неизвестным названием без разумного варианта | Сообщить отсутствие и уточнить название | Расчёт всех категорий |
| После моей зарплаты | Надёжно определить событие либо уточнить период | Использовать UI-период, забыв ограничение |
| Верни общую сумму без сравнения | Сохранить отбор, сменить формат, снять сравнение | Снять сумму/категорию/период |
| По магазинам, если такой группировки ещё нет | Честно сообщить об отсутствии функции | Выдать общий итог как выполненный запрос |

Тестирование после согласования: независимые формулировки для дат и
морфологии; границы суток/месяца/года в разных пользовательских поясах,
DST и смена пояса без сдвига банковских date-only фактов; отсутствие каждого
явно названного условия; неизвестные и
неоднозначные имена, смысловые предложения без автоматической замены;
суммы на границах/с отрицанием; формат против отбора;
сравнения; наследование №2. Сначала локальные проверки программы, затем
небольшая независимая серия реальных языковых запросов после готовности
согласованного контракта сообщений №4 и отдельного журнала испытания.

Этот документ не утверждает выполнение всех примеров текущим Registry,
не даёт AI SQL/прав записи и не подменяет дальнейшие контракты расчётов,
действий, личных каталогов и источников.
