## Как добавлять и уточнять записи

Это постоянная инструкция для каждого пополнения: отдельно напоминать её не требуется.

1. Изменять `packages/finance-core/src/catalog/merchant-dictionary.json`, увеличивать `revision`. Одна компания/услуга — один устойчивый `id`, одно отображаемое имя в принятом для бренда алфавите и регистре. Например, BelkaCar остаётся латиницей, ВкусВилл — кириллицей.
2. В `forms` добавлять конечные кириллические/латинские написания, распространённые транслитерации и словоформы. Не объединять разные бренды только из-за общей категории. Не помещать в файл пользовательские реквизиты, выписки или исполняемые шаблоны.
3. В `tokens` задавать альтернативные сочетания значимых слов, когда слова могут идти раздельно. Все слова одного сочетания обязательны; номера касс, разделители, города и банковские вставки не заменяют обязательные признаки. Для ВкусВилла достаточно VV/ВВ и KCO/KSO/КСО либо KKM/ККМ, в любом порядке; номер кассы не обязателен. Единое имя — ВкусВилл; исходные номера касс остаются видимыми в банковском описании и не удаляются из источника.
4. У всех известных сервисов Яндекса сочетания слов из профильных форм распознаются независимо от разделителей, числовых и служебных вставок. Это правило поиска действует также для базового полного справочника. Одного Яндекс/Yandex недостаточно для выбора услуги; конфликт разных сервисов не разрешается порядком записей.
5. Указывать семантическую цель `target` из проверяемого списка и уверенность: 96 — установленное назначение, 80 — предложение с обычной пометкой проверки. Для покупки указывать соответствующий расходный профиль. Реальные category/subcategory ID берутся из действующих категорий и привязок пользователя; записи не создают категории и не меняют правила финансового учёта.
6. Вендинг — продукты с уверенностью 80, даже если в торговой строке есть Metro. Это общее правило деятельности, а не перечисление отдельных касс. Явные противоречивые предметы (цветы, аптека, электроника) не относятся к продуктам этим правилом. Доставку не выводить из отсутствия других признаков — нужен её явный признак.
7. Проверять новые формы, разделители, словоформы, противоположные примеры и сохранение ручных решений. Перегенерировать снимок командой `python3 scripts/compile-merchant-dictionary.py`, проверить TS-валидатор и `scripts/test-sync-merchant-dictionary.py`.
8. Общий проверенный JSON применяется в тестовом и основном окружении. Изменения используются при следующих загрузках и по существующей кнопке распределения с ИИ; пополнение словаря само не перераспределяет историю. Ручные назначения и личные правила имеют приоритет. Невалидный файл не заменяет последний рабочий снимок.
