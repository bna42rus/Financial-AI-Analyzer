Основание: полный PDF 11.3, 35.11, 36.2–36.7, 51.3–51.5, 52.1/52.3/52.5; approved A-02/A-06/A-10/B-03/B-04/B-07 и C-07 в рамках Development. Исходные документы и baseline 1.3 неизменны. ## Входы и подтверждение

Operations передаёт точный снимок выбранных 1–1000 IDs. Data & Privacy предлагает удаление за явно заданный включительный период (московский календарь, текущая дата операции) по всем или выбранным счетам и полный сброс. Карточки Account/Counterparty предлагают удаление данных с обязательным решением сохранить или удалить саму карточку. Данные карточки охватывают effective назначения и привязанные банковские источники; они могут быть шире фильтрованного списка на экране. Обычное удаление карточки контрагента в структурном редакторе по-прежнему сохраняет операции; отдельный destructive вход прямо называется удалением данных.

Используются существующие `delete_financial` и `reset_financial`, `/finance/preview` и `/finance/commit`; миграции 0001–0016, новых таблиц/миграций нет. Preview фиксирует action ID, generation/revision, scope и зависимости. Полная смена scope при повторе не допускается. Показаны точные counts sources/components/links/history/imports, активные операции и сохранявшиеся версии объединённых операций, изменения totals, surviving related operations, правила для перенастройки и reimport warning. Вся financial History/pending previews очищается; незавершённые загрузки инвалидируются. Счётчик retainedOperations в серверном preview/receipt отдельно учитывает tombstones, которые физически удаляет canonical cascade.

Есть одно окончательное подтверждение. До него удаления нет; Escape/закрытие отменяют только намерение. Во время отправки и неопределённого сетевого результата закрытие/навигация блокируются. Retry использует прежний action ID, не создаёт новый preview и не обещает успешное удаление без receipt. Conflict отбрасывает старый preview и предлагает закрыть окно, обновить данные и проверить состав заново. Ownership, verified active session и entitlement сервер проверяет до preview и commit. Пустой scope, предел 1000 и source-account dependency имеют понятные сообщения.

## Полный сброс и пароль

Три preservation решения categories/rules/interface обязательны и не предвыбраны. Reset получает свежий `/finance/epoch`, а не финансовый граф. Поэтому есть отдельный вход при `FINANCE_SIZE_LIMIT` выше 10 000 операций. Endpoint дополнительно сообщает boolean recentAuthenticationRequired текущей собственной session; он не раскрывает credential. Commit независимо повторяет recent-auth проверку, в том числе если пять минут прошли после preview.

Password proof вводится в том же окончательном шаге, передаётся только в commit, поле сразу очищается. Flow не сохраняет пароль в pending retry, preview, receipt, localStorage или sessionStorage. После неопределённого результата пароль при необходимости вводится заново; ID остаётся прежним. Неверный пароль/устаревший вход оставляют тот же preview для исправления proof, без нового вопроса о scope. Серверная Argon2id проверка и durable subject rate limit сохранены. Текст сообщает, что identity account, session и оплаченный доступ сохраняются; финансовое удаление необратимо, обычного Undo нет.

## Очистка интерфейса

После подтверждённого receipt интерфейс сразу убирает старый graph, selection, operation/review/merge drafts, историю/результаты загрузок, глобальные фильтры и сохранённые command results; затем читает текущую собственную `/finance/state`. Ошибка повторного чтения не выдаётся за отказ выполненного удаления. Generation также сбрасывает рабочие Settings editors и пересоздаёт ImportFlow, вызывая dispose/abort локальной подготовки; старый prepared payload не переотправляется под новой версией. На другом устройстве generation распознаётся при обновлении, а серверные версии защищают отправку между обновлениями.

Оформление сбрасывается только при смене interfaceEpoch. Для обнаружения сброса после offline/reload хранится один opaque UUID `finance-interface-epoch-v1` рядом с разрешёнными visual preferences. Он не содержит financial records, amounts, identifiers, key/context или password. Сохранение interface оставляет этот epoch прежним. На устройстве с заблокированным localStorage применимая настройка остаётся в памяти; синхронизация после полного закрытия браузера тогда ограничена. Изменение epoch при смене пользователя также возвращает оформление к defaults: visual preferences пока device-scoped, полноценная per-user синхронизация не заявляется.

## Проверки и открытые границы

Восемь unit сценариев проверяют frozen IDs, отсутствие commit до подтверждения, exact retries, одно password confirmation, отсутствие сохранённого proof, conflict/access отказ, dispose и подтверждённый cleanup при ошибке чтения, interface epoch после offline. Восемь UI сценариев запускаются на desktop/mobile: selected/period/account/deep counterparty scope, cancel, uncertainty retry/no Undo, reset choices/password/appearance, stale dependencies, oversized graph и другое устройство. Два новых реальных HTTP/PostgreSQL browser journeys проверяют surviving refund, read-only cancel, потерянный уже выполненный receipt, единственный эффект удаления, проверку пароля, сохранение categories/rules со статусом needs_setup, смену key/epoch и metadata-only History. Существующие PostgreSQL tests усилены для retained counts и recent-auth metadata; privacy assertions разрешают только opaque interface epoch, registration/token storage остаётся пустым.

На 10 октября 2026 локально успешно прошли 223 теста (142 core/access/import, 73 web unit, 8 API crypto/mail), strict types, обе сборки и контроль исходных документов. Браузерные сценарии в текущем окружении не стартовали: Chromium отсутствует; попытка установки вернула пустой/повреждённый архив. Имеющийся native PostgreSQL завершился Bus error ещё на --version. Это ограничения окружения, а не подтверждённый результат browser/DB tests. Полный CI и визуальная проверка остаются обязательными: workflow сохраняет desktop/mobile reset screenshots в artifact financial-reset-previews. Изменения опубликованы в PR №31: https://github.com/bna42rus/Financial-AI-Analyzer/pull/31, поверх feature/settings-rule-editors. Полный результат CI, точный проверенный head и итог визуальной проверки фиксируются в описании PR после завершения всех checks без skip-ов.

Backups/PITR и независимый deletion replay journal, provider/AI/chat/document/budget/view/widget cascades, большие chunked selective scopes, full user account deletion, нагрузка и owner Staging acceptance остаются открыты. Текущий поддержанный scope атомарен и ограничен существующим серверным контрактом. Покупки сервисов, merge в main и Production выпуск этим блоком не выполняются.
