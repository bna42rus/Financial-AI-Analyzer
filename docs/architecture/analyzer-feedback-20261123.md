# Анализатор: причины отказов и вопросы о возможностях

Реализовано по замечаниям владельца от 23 ноября 2026. Общий источник публичных сообщений: `packages/analyzer/src/assistant-feedback.ts`; его используют workflow и HTTP-клиент. Структура интерфейса не меняется.

## Причина, последствия и следующий шаг

| Ситуация | Что объясняем | Что делать |
|---|---|---|
| Недостаточно пользовательского лимита для запроса | Это может быть недостаточный остаток для резервирования, даже если он не нулевой | Пополнить или дождаться обновления |
| Лимит не назначен / нет периода | Нет действующего назначения лимита | Проверить «Аккаунт», при активном доступе — поддержка |
| Исчерпан общий бюджет сервиса | Ограничение сервиса, а не пользователя | Поддержка / позже; пополнение не обещает исправления |
| Стоимость предыдущего запроса неизвестна | Результат платного обращения требует сверки; новые платные вызовы остановлены | Поддержка; без повторной отправки и самовольного снятия резерва |
| Изменение лимита в админке заблокировано | Остался резерв по отправленному запросу, стоимость не подтверждена | Сверить запрос и стоимость, затем повторить изменение |
| Провайдер вернул 401/403 | Отклонено подключение приложения | Проверить подключение через поддержку |
| Провайдер вернул 429 | Ограничение провайдера | Позже / поддержка; не выдавать за пользовательский лимит |
| Провайдер вернул 5xx | Ошибка сервиса модели | Позже / поддержка |
| DNS, соединение, таймаут, сертификат | Только наблюдённая сетевая причина, без предположений о балансе | Поддержка / повтор после разрешения неизвестного статуса |
| Ответ или данные стоимости некорректны | Не прошла проверка формата, условий или учёта стоимости | Ответ не используется; при неизвестной стоимости резерв сохраняется |
| Сменились данные, фильтры, период квоты | Снимок запроса устарел | Проверить текущие условия и отправить заново |
| Исчерпан предел чата, выборки или шагов | Указать конкретный предел | Новый чат / сузить выборку / разделить вопрос |
| Неоднозначный объект изменения | Нельзя выбрать объект без подмены | Точное имя и область действия |
| Ошибка бюджета | Уже существует, достигнут предел, период закончился или изменился | Конкретное исправление условий |
| Недостаточно данных калькулятора | Нужны сумма, ставка, срок; для досрочного платежа — месяц и способ | Перечислить недостающие параметры и назначение каждого |
| Невозможный результат расчёта | Платёж ниже процентов / цель недостижима в допустимом сроке | Изменить параметры; не подставлять выдуманный результат |
| Источник недоступен / другая дата / неизвестная валюта | Не подтверждены конкретные актуальные сведения | Дата/код валюты либо повтор позже; цифры не придумывать |
| Неподдерживаемое условие | Назвать ограничение; для суммы части и исключения подкатегории — отдельные причины | Предложить доступную альтернативу, не заменять условие без согласия |
| Посторонняя тема | Инструменты предназначены для финансов | Предложить финансовую задачу |
| Неизвестная ошибка | Причина ещё не установлена, дать безопасный код поддержки | Проверить диагностику; не объявлять причиной лимит без доказательств |

Ошибки отдельных шагов отчёта используют те же причины. Успешные проверенные расчёты отчёта сохраняются, связанные изменения при ошибках не выполняются. Ошибка модели не означает бесплатный вызов: фактическая стоимость учитывается по квитанции, неизвестная — остаётся на сверке. Пользователь не видит stack trace, токены доступа, ответ провайдера или банковские реквизиты. Шутки не используются в сообщениях о лимитах, потерях, долгах, сбоях и неопределённой стоимости. Для безобидного постороннего вопроса допустима лёгкая шутка только вместе с ясной причиной ограничения.

## «Что ты умеешь?»

Справочные вопросы распознаются до платной модели. Ответы описывают подключённые инструменты: анализ операций, калькуляторы, первичные источники, подготовку бюджетов, категорий, правил и контрагентов. Недоступное подключение инструмента не выдаётся за доступную функцию. Создание бюджета по справочному вопросу не запускается. Подтверждение изменения обязательно. Конкретные команды с суммой/условиями продолжают обычный путь через модель, проверку и предпросмотр.

Вопросы: «Что ты умеешь?», «Чем можешь помочь?», «Сможешь создать бюджет?», «Умеешь ли рассчитать кредит?», «Можешь создать правило?», «Умеешь объяснять простым языком?», «Можешь показать курс валют?». Для неизвестной возможности не обещается произвольное действие. Справка не сбрасывает условия последнего расчёта и не расходует токены модели.

## Проверка конкретного аккаунта на сервере

`sudo python3 scripts/diagnose-analyzer-account-staging.py --email '<адрес>'`

Скрипт предназначен только для Staging на локальном порту 5411, выполняет read-only транзакцию, не вызывает модель и не изменяет резерв. Выводит доступный лимит, состояния последних обращений и открытых резервов, безопасные коды транспорта. Не выводит email, тексты вопросов, банковские данные и секреты. Исчерпание лимита и открытый резерв могут существовать одновременно; различать их нужно по данным, а не скриншоту.

Для снятия неизвестного резерва необходим подтверждённый результат провайдера или отдельная документированная процедура сверки; время ожидания и нулевой лимит не доказывают отсутствие расхода. Эта поставка не меняет денежные данные аккаунтов и не снимает резервы автоматически.

## Восстановление незавершённого учёта

После сообщения владельца об отсутствии списания добавлена отдельная адресная процедура `scripts/reconcile-assistant-reservation-staging.py`. Требуются email выбранного аккаунта, точный UUID запроса, ожидаемая сумма резерва и явное подтверждение оператора `--apply --attest-unbilled`. Сначала проверяются состояние старого запроса и целостность агрегатов, затем до изменения создаётся приватная запись подтверждения оператора. Коррекция атомарная и повторяемая, не меняет лимиты/фактические расходы, не повторяет запрос и не подделывает квитанцию провайдера: provider usage остаётся unknown, а резерв снимается по подтверждению владельца. Работающий запрос и изменившиеся условия останавливают процедуру. Только база finance_staging на localhost:5411.

В workflow квитанция с известными токенами и проверенные коды сбоя сохраняются до изменения денежного учёта. Сохранённая usage позволяет восстановить списание при следующем открытии Анализатора/запросе без повторного HTTP-вызова модели. Операция идемпотентна, использует исходные тариф и период; неизвестная usage автоматически в нулевую не превращается. Если подготовка сорвалась после создания текущего резерва, но до HTTP, транспорт отдельно удостоверяет отсутствие отправки: снимается только резерв, созданный этой попыткой. Обнаружение ранее отправленного запроса не является таким доказательством и не снимает старый резерв.

Восстановить точную сетевую причину исторического запроса без сохранённой диагностики нельзя. Новые отказы сохраняют безопасные коды транспорта, фазы и время. Обрывы связи и отсутствие квитанции у провайдера полностью исключить невозможно: истинно неизвестный расход по-прежнему требует сверки, но его причина и процедура разбора теперь явны. Автоматическое обнуление по таймеру или бесконтрольная повторная отправка запрещены.
