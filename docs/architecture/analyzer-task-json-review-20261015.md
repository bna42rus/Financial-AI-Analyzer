# Полный аудит первого JSON-mode прогона GPT-OSS

15 октября 2026. Источники: операторский результат 52/92, все 170 сохранённых
gate/proposal cache records и исходный executable commit `8105e713`.
Основание продуктовой логики: PDF 26.1–26.8 и закрытый task contract.

## Что воспроизведено

Все 170 исходных wire SHA совпали при реконструкции inputs. Offline workflow
повторил **52/92**: development **36/68**, independent repetitions **16/24**.
Goldens, scoring, ошибочные parent states и исторические расходы не менялись.
28 holdout не открывались. Вызовов модели/HTTP и изменений ledger: **0**.

Из 40 неуспешных шагов 26 не имеют более ранней ошибки в сценарии, 14 имеют
`earlierFailure`. Этот флаг не доказывает, что у последующего шага нет своей
ошибки. Reasons: 14 invalid_proposal, 7 model_clarification, 4 metric_required,
13 query/binding mismatch, по одному unrelated и ambiguous.

## Общие механизмы

| Механизм | Наблюдение | Требование к следующему контракту |
|---|---|---|
| Выбранный период | `single-01` трижды уточняет период, который применяет сервер | Явно объяснить server-owned defaults; не отправлять значения filters ради этого |
| Новая задача / продолжение | `money-2` создаёт new и снимает порог; `fixed-2` получает metric_required при имеющемся parent | Короткое изменение связывать с задачей, сохранять остальные условия; new требует собственного metric |
| Категория / продавец | Одинаковый `single-05` дважды выбирает merchant и один раз categories | Определить роль названия; owned resolution остаётся локальным, неизвестное имя не расширяет scope |
| Формат | `manual-3` игнорирует «итог одной суммой» | Формат меняет только grouping, не период/категории/порог/сравнение |
| Неподдержанное | `single-31` заменяет группировку по магазинам обычным итогом | Unsupported остаётся unsupported, похожий Query не является корректным ответом |
| Gate | Ключевая ставка названа unrelated; category follow-up — ambiguous | Финансовая тема и поддерживаемый инструмент различаются; контекст влияет на короткое уточнение |
| Диагностика | 14 rejected JSON заменены null | В новых попытках сохранять encrypted protocol value и безопасный fixed code после durable usage |

В `money-2` ожидаемый результат 100000 minor units (1000 ₽) превратился в
2100000 (21 000 ₽). Финансовое ядро верно посчитало переданный более широкий
scope: ошибка находится в выборе задачи/условий, а не в арифметике модели.

## Почему проверены и успешные шаги

В `single-19@0` и `single-20@1` модель выставляет grouping/comparison=none
с цитатами из условия суммы/операций. В новой задаче это совпало с defaults,
поэтому текущий strict result правилен. Такие примеры нельзя автоматически
считать доказательством правильного переноса условий в продолжении.

У двух повторов attention текущие totals и видимые points совпали с golden,
но operationCount и сохранённый attention filter различаются. Это может
повлиять на drill-down и следующий запрос. Долгосрочная эквивалентность не
доказана; **52/92 не пересчитаны в более красивый показатель**.

В шести из 12 repeated groups одинаковые proposal wire bodies дали разные
semantic outcomes: attention, leaf, grouping, comparison, relative-period,
money-signed. Значение temperature=0 не является доказательством наблюдаемой
стабильности этого сервиса. Никакая точность по произвольным похожим вопросам
на основе одного успешного примера не утверждается.

## Изменения, подготовленные после аудита

1. Permanent offline audit проверяет конкретный export SHA, все wire identities,
   реальные решения и прежний score. Подмена cache/успешного ответа, потеря
   записи и другая identity отклоняются. Отдельно видны повторы и scope risks.
2. Rejected-payload sink вызывается после fsync usage receipt и invalid cache.
   Исходное JSON value шифруется AES-256-GCM в root-private evidence, не
   выдаётся в обычный отчёт. Сбой sink останавливает выполнение без повторной
   оплаты; replay не повторяет ни POST, ни sink. Старые 14 values не восстановлены.
3. Отдельный неоплачиваемый `task-prepared-contract/1` описывает все указанные
   механизмы общими правилами и двумя generic shape examples. Это подготовка,
   а не заявленная новая точность. Старая авторитетная схема и parser прежние.
4. В prompt text повторяющиеся подсхемы вынесены в локальные `$defs/$ref`.
   Exact expansion возвращает исходную схему; независимая валидация 325
   observed/mutated values не выявила разницы. Capabilities не дублируются в
   user input. Это сокращает bytes; token/рублёвая экономия ещё не измерена.

Никаких semantic regex-подмен неверного gate/ответа, корректировки goldens,
автоматического обучения по плохим решениям или runtime enablement нет.
Подготовленный контракт не подключён к новому paid experiment. Полный новый
run требует отдельной frozen identity и budget admission; повтор старого
CLI остаётся бесплатным отчётом архивного source.
