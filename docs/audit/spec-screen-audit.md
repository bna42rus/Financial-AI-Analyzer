# Проверка полной спецификации и экранов — 9 октября 2026

Это исторический срез. Актуальные расхождения, исправления и проверка всех пунктов:
[аудит 10 октября 2026](comprehensive-spec-audit.md). Указанные ниже отсутствующие
функции и числа тестов отражают состояние на дату этого среза.

Основа: полный PDF (75 страниц), Word (контекст), согласованная база 1.3, все A/B/C/E с установленным приоритетом. Оригинальные документы и прежние статусы registry не изменены. Сверено 455 записей PDF и 39 согласованных дополнений; Word разобран отдельно по разделам. Наличие кода/теста в таблице доказывает только указанную узкую часть. Полный пункт может содержать несколько обязательных сценариев; **ни один пункт не объявляется выполненным целиком этим аудитом**. Отсутствующий модуль назван работой разработки, а не вымышленным внешним блокером.

## Исправлено в рабочем интерфейсе

- Четыре основных раздела и десять вложенных Настроек; исчез ошибочный возврат подразделов к Операциям.
- Новый аккаунт начинает с загрузки первой выписки; демо не выдаётся за сохранённые финансы.
- Общие даты/банк/счёт/категории отправляются закрытыми параметрами в серверный расчёт. Новым фильтрам не подставляются старые итоги.
- Положительный expense отображается как «Уменьшает расходы», отрицательный income — «Уменьшает доходы»; other — «Другое».
- Банковский exact timestamp не сдвигается при смене profile timezone; текущие российские adapters используют Moscow bank-day. System timestamps остаются в timezone профиля.
- Расшифровка gross/refunds/net/income/unresolved/neutral/excluded и связь Обзор→Операции; исправлена ширина графической полосы.
- Persisted History: последняя 30-дневная история, kind filter, история отдельной операции, pagination, before/after, проверка одиночной и выбранной отмены. Bulk selection фиксируется и ограничена 100 actions.
- Настройки используют сохранённые счета/категории/контрагентов. Доступные rename/create/hide/status/type/analytics/loan-model commands защищены preview/commit/revision/idempotency. Простое reversible rename сохраняется сразу; финансовый пересчёт требует показанных последствий.
- Потеря financial access немедленно удаляет финансовое содержимое с экрана; ограниченный аккаунт остаётся доступен.
- Theme/density/textSize/motion сохраняются после reload только как 4 визуальных значения; raw files, passwords, key, операции, диалоги, filenames и drafts не записываются в browser store. Reset оформления не удаляет финансы.
- Network uncertainty повторяет тот же action, ошибки загрузки после commit блокируют следующую правку до refresh; поздний ответ закрытого workspace игнорируется.
- Переход между разделами во время первой загрузки сохраняет ответ текущего запроса: navigation больше не выполняет cleanup рабочего workspace. Отдельный тест удерживает первый response и меняет экран до его доставки; до исправления он воспроизводил зависание на desktop/mobile, после — проходит без ожидания polling timer.
- Поздняя загрузка карточки операции не возвращает её после перехода в другой раздел или финансового сброса. Навигация и смена generation закрывают текущий detail context; response дополнительно сверяется с текущей generation. Оба сценария воспроизведены до исправления и защищены тестами desktop/mobile.

## Что остаётся разработать и проверить

Приоритет до AI: full imports/cancellation/provenance/dedupe decisions и рабочие links/components/rules/review/structural editors; затем budgets, полноценные Operations filters/bulk/saved views и customizable Overview. Backend support для некоторых структурных операций уже есть, UI ещё нет. Нельзя принять их одним наличием endpoint.

Для AI нужны versioned Registry, authoritative tools, usage/quota/provenance/deletion, локальная работа с документами и quality/privacy corpus. Реальные provider credentials сами по себе это не реализуют.

Timeweb/account setup не мешает synthetic разработке. Внешние prerequisites: полный Staging runtime и пробный deployment/rollback; реальный PostgreSQL roles/backups/PITR/restore; KMS, independent monitoring, Yandex AI trials/Postbox, DNS/HTTPS, legal/support/retention/RPO/RTO и owner acceptance. Ничего не куплено, не объединено с main и не выпущено в Production.

## Результаты проверки

До первого CI локально прошли: неизменность исходников; 133 core/access/import теста; 53 web unit/flow теста; 8 crypto/mail tests; TypeScript web/admin/API; обе сборки; полный прогон 82 web UI сценариев (desktop/mobile, без повторов, 55,3 с), включая 10 новых connected UI сценариев; 16 admin UI. Итого 292 успешные локальные проверки. Обновлённые assertions проверяют ровно 4 визуальных значения и отсутствие финансовых данных/drafts.

Первый полный CI дополнительно прошёл 251 PostgreSQL/security тест, но два HTTP/browser сценария обнаружили отмену первого чтения при быстрой навигации; это не успешный полный прогон. После исправления локально повторно прошли TypeScript/web unit (53 теста) и все 12 connected UI сценариев без повторов, включая два новых регрессионных сценария. Фактический результат полного CI окончательного кода фиксируется в PR, а не выводится из прежнего локального коммита или суммы частичных прогонов.

Следующий CI подтвердил оба HTTP/browser сценария редактирования, но обнаружил устаревший тест отзыва доступа: нажатие кнопки «Аккаунт» соревновалось с немедленным удалением финансового workspace. Тест теперь ожидает запрещённый финансовый server response и проверяет отсутствие финансового результата, навигации и открытия приложения; исчезновение финансового экрана не объявляется ошибкой продукта. Этот частичный прогон также не считается полным успешным CI.

Полный CI коммита d248ecf105ba397d73b5d911121b8bdb221bd1a2 прошёл 551 тест (133 core + 53 web unit + 8 crypto/mail + 251 PostgreSQL/security + 6 real HTTP/browser + 84 web UI + 16 admin UI), run 37894571873. Последующая проверка lifetime выявила позднее открытие карточки после навигации и после финансового сброса. Новые регрессионные сценарии воспроизвели каждую проблему на двух размерах экрана до исправления; после него локально прошли TypeScript/web unit (53) и все 16 connected UI сценариев без повторов. Этот прежний зелёный CI не объявляется проверкой последующих правок; результат окончательного коммита указывается в PR.

Следующий прогон выявил зависимость прежнего checkpoint test от скорости PostgreSQL: вызов scheduler выполнялся раньше next_attempt_at (в production-коде следующий checkpoint планируется через 10 мс). Test fixture теперь явно задаёт будущую/прошедшую дату, проверяет отказ до срока и обработку после срока, а также completed, нулевой pending и удаление dispatch без прямого drain fallback. Проверки counts, consumed instances и provenance сохранены; runtime imports не менялись. Полный результат этой окончательной версии также фиксируется в PR.

Полная проверка окончательного коммита, включая PostgreSQL и 6 real HTTP/browser journeys, запускается в PR ветки feature/spec-screen-audit к feature/live-operation-review. Её фактический результат, run URL и commit SHA фиксируются в описании PR после завершения; локальные проверки и ссылки на тесты в матрице не заменяют этот результат. Connected interface tests с synthetic HTTP adapter отдельно от real PostgreSQL/HTTP browser journeys. Mobile viewport Chromium не объявляется настоящим Safari.
